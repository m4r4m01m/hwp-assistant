# 편집 중인 문서에 표준·부분 디자인 적용

2026-10-25 로컬 작업 기록. 시작 코드: `a013b8633e2d488d0c1a4799f9698ec310bcb92d`의 QA 체크아웃과 이번 미커밋 기능 변경. 이 문서는 구현 범위와 아래 실행 검증을 구분하며 원격 병합·운영 배포·한컴 검수의 완료 보고가 아니다.

## 사용 흐름

문서 편집의 **문서 서식·디자인**에서 적용 범위를 고른다. **선택한 부분**은 현재 문단이나 표에 제목·표 디자인을 적용한다. 카드의 모양은 설명용 예시이며 실제 글꼴·너비·줄바꿈은 해당 문서의 한글 엔진 결과로 확인한다. 직접 고른 카드의 클릭은 부분 디자인 적용 요청이다. **적용 전 보기**를 누르면 실제 문서의 전후 화면을 먼저 확인할 수 있다.

**문서 전체**는 등록한 문서 표준 또는 고정 별첨 1·2·3의 지원 서식을 선택하고 전후 화면을 확인한 다음 적용한다. 적용 후에도 일반 편집 문서의 저장 상태를 확인해야 한다. 미리보기 API는 문서나 버전을 저장하지 않는다. 편집기 적용·서버 저장·다운로드는 서로 다른 단계다.

양식 보관함의 표·제목 예시는 이 편집 흐름으로 연결한다. 예전 문서 전체 양식으로 새 문서를 만드는 기능, 문서 표준 자체를 편집·등록하는 기능과 구분한다. 이 변경은 문서 표준 편집 화면의 예시나 저장값을 자동 변경하지 않는다.

## 이번 적용 범위

| 대상 | 변경 범위 | 유지하는 내용 |
|---|---|---|
| 본문 문단에 제목 디자인 | 제목 글꼴·크기·색·문단 간격·들여쓰기와 파란 상하선 기반 제목 프레임 | 원문 글자, 문단 위치, 다른 문단·표·용지 설정 |
| 표에 표 디자인 | 단순 직사각형 표의 셀 글자·문단 서식, 선·첫 행 음영·셀 여백·정렬·최소 높이·본문 폭 대비 너비 | 셀 내용·행열 수·개체 순서, 다른 표·문단·용지 설정 |
| 한 칸 제목 상자에 제목 디자인 | 인식된 제목 상자의 글자와 상하선, 필요한 최소 높이 | 상자 내용·너비·위치·셀 여백. 기존 높이를 줄여 내용을 자르지 않음 |
| 문서 전체에 표준 | 용지·여백, 기호/번호와 기존 제목 프레임으로 확인되는 문단의 글자·문단 서식, 지원하는 표의 서식 | 전체 원문·문단 순서·기호·주석 표식·표지 및 목차 구성, 확인 불가능한 문단/표의 기존 서식 |

본문의 기존 부분 진하게·기울임·밑줄과 윗첨자·아랫첨자는 유지하며 글자 색은 선택한 서식을 따른다. 명시적으로 고른 제목 디자인은 제목의 진하게·기울임·밑줄 설정도 적용한다. 문서 전체 적용에서 별첨을 선택해도 새 표지·목차를 만들거나 기존 것을 제거하지 않는다. 따라서 동일한 서식값을 가진 별첨끼리는 현재 문서의 구조가 자동으로 서로 변환되지 않는다. 쪽 배치가 바뀐 기존 목차에는 명시적인 갱신이 필요하다.

일반 문단을 제목 프레임으로 꾸밀 때는 설정한 문단 앞뒤 간격에 프레임 바깥쪽 여백과 선 두께의 반을 더해 자리를 확보하고, 선 두께만큼의 추가 틈을 둔다. 제목선이 다음 문단·표 위에 그려지거나 표의 테두리와 붙어 보이지 않도록 하는 배치 보완이며 내용이나 이웃 문단의 서식은 바꾸지 않는다. 같은 디자인을 반복 적용해도 이 간격이 누적되지 않는다.

표준의 새 초안 작성 지시, 괄호 요약어·주석/번호 표현 변경, 내용 요약과 문장 재작성은 현재 문서에 사후 적용하지 않는다. 등록한 표·제목 디자인의 캡션·주석·표지 날짜 설정도 선택한 표나 문단 밖의 내용을 변경하는 데 사용하지 않는다.

## 선택과 지원 제한

- 첫 구역의 본문 문단, 직접 선택한 표 또는 그 표의 첫 단계 셀을 대상으로 한다. 표의 `control` 위치는 표만 센 번호가 아니라 고정 엔진의 모든 개체를 센 실제 인덱스다. 알 수 없는 개체는 인덱스를 추정하지 않고 거부한다.
- 표의 병합 셀·중첩 표·개체가 있는 셀·불규칙한 행열은 부분 적용을 거부한다. 문서 전체 적용에서는 이런 표와 화살표 셀을 사용한 도식 표를 유지하고 개수를 안내한다.
- 한 칸 표를 무조건 제목으로 보지 않는다. 기존 파란 상하선·좌우선 없음 또는 이 기능으로 기록된 제목 서식으로 확인된 제목 상자만 제목 디자인을 받는다. 제목 상자와 같은 본문 문단에 일반 텍스트가 있으면 부분 적용을 거부한다.
- 일반 문장이나 역할이 불명확한 문단은 기존 서식을 유지하고 개수를 안내한다. `(금)` 같은 요일을 문단 번호로 바꾸지 않는다. 원문 기호/번호를 제거하거나 재작성하지 않는다.
- 현재 변환은 단일 본문 구역·단일 단, 10MB 이하 HWPX에 한정한다. 필드·지원하지 않는 문서 구조는 실패하며 현재 편집 버퍼는 그대로 둔다. 머리말·각주·미주·도형 글상자와 중첩 표 안의 선택을 부분 적용 대상으로 추정하지 않는다.

## 보존·권한 계약

`GET /api/editor-designs`는 해시로 고정한 기준서 표·제목 디자인, 해당 계정의 활성 디자인 조각과 revision-3 문서 표준만 반환한다. 내장 별첨과 사용자 표준의 기존 ID·설정·파일은 변경하지 않는다. 숨기거나 교체한 표준·삭제한 디자인은 새 적용에 사용할 수 없다.

`design-preview`는 현재 미저장 HWPX의 SHA-256, 선택 대상, 디자인/표준 ID와 해시, 기준 버전 및 편집 임대를 검사한다. 변환은 기존 글자·문단·테두리 정의를 복제하고 필요한 참조만 바꾸며 기존 정의를 덮어쓰지 않는다. 원문 텍스트·제어 개체의 구조를 검사하고 원래 ZIP 리소스 바이트를 그대로 복사한다. 이전 줄 배치 캐시는 내용이 아니므로 새 렌더링에 쓰지 않는다.

별도 한글 엔진에서 결과를 열고 `design-verify`가 예상한 문단·개체·서식과 엔진 출력을 대조한다. 기존 서식 정의 누락, 원문/자원 변경, 예상 밖 ZIP 리소스 추가를 거부한다. 프런트엔드는 반영 직전 `design-check`와 문서·버전·임대·선택·현재 버퍼를 다시 확인한다. 준비 도중 다른 편집을 하면 그 편집을 덮어쓰지 않는다. 자동 저장 보류, 준비 취소, 적용 직후 되돌리기는 기존 편집기 교체 경계를 따른다.

## AI 추천의 역할

문서 대화는 편집 시점에 고정한 현재 문서와 선택 위치를 바탕으로 서버 카탈로그에 있는 ID·해시를 추천할 수 있다. 선택 부분의 텍스트와 제목 상자 여부는 같은 HWPX 스냅샷에서 읽고, 긴 내용은 발췌 여부를 표시한다. 카탈로그 밖의 임의 디자인을 모델이 실행 코드나 서식값으로 만들어 적용하지 않는다.

추천은 적용이 아니다. 사용자가 제안을 선택하면 같은 서식 미리보기 경로로 들어가며, 질문 후 문서·버전·선택 대상이나 카탈로그가 바뀌었으면 다시 확인해야 한다. 기존 문단 AI 수정도 별도 비교·승인 경로를 유지한다. 실제 모델 추천의 적합성은 합성 응답 계약 시험과 구분하여 검수한다.

## 검증 기록

합성 파일을 사용한 [집중 백엔드 시험](../backend/tests/test_editor_designs.py)은 **21개**를 통과했다(16.61초, 기존 의존성 경고 2개). 최종 여유 간격 보완 후 영향받는 3개를 다시 확인했다(2.60초). 문단/표별 대상 격리, 실제 개체 인덱스, 한 칸 제목 상자와 다시 적용, 일반 표 오인 방지, 병합 표 거부/전체 적용 안내, 원문·ZIP 리소스·기존 저장 버전 보존, 입력/서식 해시·선택·권한·임대·기준 버전, 다른 계정의 표준/디자인 차단, 엔진 출력의 글자·자원·기존 서식 변경 거부를 확인했다. 추가한 제목 간격 시험은 기존 설정에 프레임의 바깥 공간과 보이는 틈을 더하는지와 반복 적용 불변성을 두 단위 분기에서 검사한다. 이 시험의 엔진 출력 입력은 합성 결과이며 실제 rhwp 검증을 대신하지 않는다.

로컬 격리 환경의 실제 rhwp 브라우저 통합 **3개 시나리오**가 통과했다. 문서의 부분 표·제목 적용과 되돌리기, 전체 표준 적용 및 오래된 준비 결과 차단을 확인했다. 이후 화면 검수에서 제목선과 뒤따르는 표가 겹친 것을 발견해 위 간격 보완을 적용했다. **보완 후 실제 화면에서 제목의 아래 파란 선과 다음 표의 위 테두리 사이 흰 간격을 확인했다.** 같은 실행의 실제 HWPX에서 앞뒤 여백 791 HWPUNIT(구 단위 분기 1582), 프레임 offset 366을 대조했다. 이는 해당 합성 사례의 시각 확인이며 모든 문서 배치에 대한 보장이 아니다.

실제 Codex `gpt-6.1-sol` 호출은 합성 자료로 **1회**, 약 **15초**에 완료되어 카탈로그 안의 서식 추천을 반환했다. 이는 한 요청의 실제 모델 성공이며 모든 문서에서의 추천 품질 보장이 아니다. 모델 추천의 적용은 별도의 사용자 선택과 서식 검증 경로를 따른다.

최종 수정본의 실제 rhwp 디자인 시험은 **4개 시나리오**를 통과했다. 보관함 카드 → 문서 선택 → 편집기 적용, 적용 뒤 다른 미리보기를 취소해도 기존 되돌리기 유지, 지연된 화면 응답 후 취소·새 미리보기, 오래된 선택/본문 차단, 검증 응답 유실 재확인, 전체 표준 비교·확대·명시적 저장·재열기를 확인했다. 공유하는 편집기 교체 코드의 기존 블록 삽입 시험도 **1개** 통과했다. 실제 rhwp에서 원문·원본 다운로드·서버 버전 보존을 검사했으며, 이 5개 시험에서는 모델을 호출하지 않았다.

AI 계약의 백엔드 고유 **58개**(기존 33 + 신규 25), 모의 UI **14개**(기존 생명주기 7 + 신규 제안 7), 선택 위치 브리지 단위 **5개**가 통과했다. 첫 문단의 구역/쪽번호 메타데이터는 허용하되 실제 개체는 제외하며, 제목 상자에는 제목 디자인만 추천하도록 확인했다. 실제 모델 1회와 모의 응답 시험 결과는 합산하지 않는다. TypeScript와 잠금 파일에 일치하는 Vite 7.3.7 프런트 빌드도 통과했다. [검증 근거](evidence/editor-designs-2026-10-25.json).

이번 엔진은 rhwp 0.8.6의 기존 **진단 코어**에 읽기 전용 선택 위치 브리지를 반영한 로컬 빌드다. 브리지 SHA-256은 `5654a7170e7c061193a2419b1b123f4bb2cdc166ab358e8c82c01e0060b81c29`, WASM SHA-256은 `e2a21d71f65045ed0d432e33859590e1ae229a654109e4a1f4ceb4aa2eb3b2e0`이다. 최적화 release 재빌드·운영 배포·한컴 2018·폐쇄망 검수를 수행한 것은 아니다. 사용자 앱의 기존 문서와 원본·과거 버전을 이번 시험 자료로 변경하지 않았다.
