# 실시간 보고서 작성

2026-10-08: 완성된 보고서를 문단 단위로 재생하는 기존 화면에 실제 생성 중 텍스트 수신을 연결했다. 문서함의 **보고서 작성 → 새 요청**에서 사용한다. 이전에 완료한 보고서는 다시 모델을 호출하거나 스트리밍 이력을 꾸며 내지 않는다.

## 생성과 표시

보고서 전용 실행은 `codex app-server`의 `item/agentMessage/delta`를 읽는다. 실제로 받은 구조화된 응답의 제목·요약·절 제목·본문 문자열만 임시 화면에 표시한다. 끊어진 JSON/이스케이프/유니코드는 표시 전용 파서가 처리한다. 추론 원문, 내부 프로토콜, 도구 응답 원문은 화면이나 검증 자료에 기록하지 않는다. React 텍스트 렌더링을 사용하며 모델 문자열을 HTML로 해석하지 않는다.

서버는 약 200ms 간격으로 소유자별 작업의 진행 스냅샷을 보관한다. 브라우저는 이전 조회가 끝난 뒤 400ms 후 다음 조회를 보내므로 중복 조회와 응답 역전을 피한다. 원본 모델 전송은 스트리밍이고 브라우저 전달은 짧은 주기의 인증된 HTTP 조회다. WebSocket/SSE를 구현했다고 표현하지 않는다. 새로고침은 같은 작업 ID의 최신 스냅샷을 읽으며 새 모델 요청을 만들지 않는다. 긴 목록에는 진행 본문을 포함하지 않는다.

자료 조회 이벤트가 실제로 발생할 때 검색어/조회 대상과 완료 건수를 표시한다. 자료 조사 중에는 본문이 없을 수 있다. 본문이 도착하면 바로 누적 표시하고, 완료된 내용은 한글 서식 적용 중에도 유지한다. 최종 JSON 검증과 기존 exact command·영수증 검증을 거친 뒤 편집 가능한 rhwp HWPX를 연다. 생성 중 초안은 확정 문서가 아니며 저장 버튼을 제공하지 않는다. 사용자가 `초안 확정·서버 저장`을 누르는 기존 경계는 유지한다.

220ms 문단 표시 대기는 기본으로 껐다. 필요하면 `작성 과정 천천히 보기`를 켤 수 있으며, 이는 모델 생성 속도가 아니라 문서 적용 단계의 표시 속도다. HTML 미리보기의 15pt 본문·22pt 제목·들여쓰기·본문 폭·검은 글자색을 기준 서식에 더 가깝게 맞췄다. 최종 행/쪽 배치는 실제 HWPX 엔진에서 계산한다. 모든 서식 깨짐을 해결했다고 주장하지 않으며, 한컴에서의 시각적 검수와 자동 목차/표/이미지 템플릿 확대는 별도다.

## 실행·저장 경계

기존 ChatGPT 로그인을 사용하며 선택된 Codex 모델을 유지한다. API 키·다른 제공자·유료 대체·모델 다운로드를 추가하지 않는다. 문단 후보 생성용 `codex_runner.py`, 실행 슬롯, 권한·임대·영수증·저장 키 로직은 변경하지 않는다.

app-server에는 현재 `--ignore-user-config`가 없어 보고서 명령에서 도구·작업 지침·읽기 전용·승인 금지·기본 서비스 등급·medium 추론 설정을 명시한다. 모델 ID는 기존 설정에서 고정한다. thread 생성 전에 모든 설정된 MCP를 비활성화하고, 사용자 제공자 URL/기본 OpenAI 제공자 재정의가 있으면 실패 처리한다. 실제 thread 응답의 모델·제공자·샌드박스·승인 정책·추가 지침 파일 유무를 확인한다. 인증이나 설정 파일은 수정/복사/제공하지 않는다. 관리 정책을 우회하지 않는다.

새 stdio 처리기는 기존 `WindowsJob` 소유 프로세스 보호를 재사용한다. 응답 큐·줄 길이·텍스트 크기를 제한하고 읽기/쓰기 대기, 시간 초과, 중단 시 자신의 자식 프로세스와 읽기/쓰기 스레드를 정리한다. 서버 측 생성 작업 수 제한은 기존 실행 슬롯 그대로다. 로컬 실행 종료가 원격 추론 취소를 보장하는 것은 아니다.

중단/만료 후 진행 기록과 ready 게시는 문서가 아닌 보고서 작업 행의 최신 상태를 잠그고 확인한다. 완료가 먼저 게시된 작업은 후속 중단으로 훼손하지 않는다. 중단한 작업의 부분 초안은 읽기 전용으로 남고 새 요청과 섞이지 않는다. 실패한 부분 응답을 최종 보고서로 대체하거나 자동 재요청하지 않는다. `context_used=false`는 유지한다.

## 시간 측정

- `startup_ms`: 로그인 확인 및 thread 준비까지.
- `first_text_ms`: 첫 표시 가능한 텍스트 도착까지.
- `generation_ms`: 생성 시작부터 모델의 정상 완료 이벤트까지.
- `research_ms`: 관찰된 자료 조회 이벤트 구간의 합집합. 겹치는 호출 시간을 중복 합산하지 않는다.
- `text_ms`: 첫 글 도착부터 정상 완료까지.
- `client_apply_ms`: 브라우저가 보고한 준비 문서 로드·exact command 적용·출력 확인 시간.
- `layout_ms`: 서버의 출력 검증·서식 계산 시간.

위 시간 중 첫 글/자료 조회/텍스트 생성은 전체 생성 시간과 겹친다. 서로 더해서 총 지연으로 계산하지 않는다. 네트워크 전달과 최종 브라우저 파일 로드까지 모두 분해한 측정은 아니다. 과거 보고서의 3분을 새 계측으로 소급 산정하지 않는다.

검증 명령과 결과, 최종 소스 해시는 `docs/evidence/report-stream-2026-10-08.json` 및 `report-stream-manifest-2026-10-08.json`에 기록한다. 이전 날짜별 증거는 덮어쓰지 않는다. 실제 Codex 시험은 짧은 무검색 합성 보고서로, 금융권 웹 조사 보고서의 완료 시간과 비교하지 않는다. 실제 모델·실제 엔진·모의 모델 이벤트·자동 클릭·사람 승인을 구분한다.

공식 프로토콜: [Codex App Server](https://learn.chatgpt.com/docs/app-server#item-deltas). 설치된 CLI에서 생성한 JSON Schema와 무추론 thread 사전 확인, 합성 stdio 프로세스 및 실제 Codex 응답으로 검증했다.
