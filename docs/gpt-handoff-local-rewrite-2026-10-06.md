## 구현한 핵심

기존 “미저장 문단 스냅샷 → 후보 2개 → 사용자 승인 → rhwp exact command → 영수증 → 서버 저장 → 적용 이력”을 로컬·사내 OpenAI 호환 모델도 사용할 수 있게 했다.

1. 서버 설정 `HWP_REWRITE_PROVIDER=codex|llm`을 추가했다. 기본은 `codex`이며 자동 전환하지 않는다. `llm`은 기존 `LLM_PROVIDER=openai-compatible`, `LLM_BASE_URL`, `LLM_MODEL`, 선택적 `LLM_API_KEY`, `LLM_TIMEOUT_SECONDS`를 사용한다.
2. `LlmProvider.rewrite`와 작은 로컬 실행기를 추가했다. 기존 `RewriteTask`, `RewriteCandidate`, `Application`, 버전 저장을 재사용하며 DB 마이그레이션·새 편집기·새 AI 프레임워크는 없다.
3. 로컬 경로는 Codex 로그인/프로세스/MCP를 요구하지 않는다. Codex 경로의 `HWP_CODEX_USER` 제한은 유지한다. 로컬 요청도 서버가 지정한 경로, 문서 editor/owner, 본인 임대, 기준 버전 검사를 통과해야 한다.
4. 요청 순간의 미저장 스냅샷·모델·개선 지시를 고정한다. 모델에는 선택 문단과 개선 지시만 보낸다. 기존 대화의 목적·확정 사실·작성 기준·대화 내역은 이번 두 후보 요청에 포함하지 않으며 UI와 실행 근거에도 `context_used=false`로 표시한다.
5. 후보는 정확히 2개, 서로 다른 비공백 문자열, 이유 필수, 추가 필드/중복 JSON 키/잘린 응답/코드 블록/잘못된 JSON 거부다. rhwp 0.8.6 exact command가 실제로 허용하는 **최대 4,000 Unicode 코드포인트·단일 문단·줄바꿈/탭 금지**와 맞췄다. 이유는 최대 2,000자다. JSON schema 지원을 추측하지 않고 일반 JSON 프롬프트와 서버 검증을 쓴다.
6. 모델 호출 동안 DB 쓰기 트랜잭션/문서 행 잠금을 잡지 않는다. 호출 전후 권한·임대·기준·작업 상태를 확인하고, 유효 후보 2개와 ready를 함께 commit한다. 생성만으로 HWPX/버전/Application은 바꾸지 않는다.
7. 같은 작업 ID는 한 번만 실행하고 같은 ID의 다른 내용은 충돌 처리한다. 공개 후보 주입 경로는 만들지 않았다. 로컬 작업에 MCP 실행 토큰을 발급하지 않는다.
8. 현재 설정과 과거 작업의 실제 제공자·모델을 구분한다. 원문/스냅샷/정규화된 모델 입력 해시와 실행 결과를 남기며 비밀키·임대 지문을 공개하지 않는다. 과거 provider 필드가 없는 작업은 기존 Codex로 해석하고 모델을 임의로 채우지 않는다.

고정 엔진의 추가 제한도 확인했다. **4,000자 이내라도 적용으로 문서 페이지 수가 바뀌면 거부한다.** 길이 계약 통과를 항상 적용 가능한 후보라고 해석하지 마라. 페이지 수/비대상 내용 보호를 끄지 않고 이 제약을 문서화했다.

## 함께 수정하고 진행한 후속 작업

- 생성 요청 응답 유실 시 열린 탭에 같은 ID·원문·지시를 보관해 재확인한다. 승인하거나 작업 결과 수신을 중단하면 해결된 요청을 해제해 새 지시를 시작할 수 있다.
- 승인 저장 commit 뒤 응답이 유실되면 기존 UI가 이미 저장된 승인 이력과 현재 기준을 충돌로 판단하던 결함을 고쳤다. pending 출력/키를 먼저 재시도하고 중복 버전을 만들지 않는다.
- 승인 응답 유실, 적용 영수증 응답 유실, 영수증 유실 후 추가 입력도 실제 rhwp + 모의 HTTP 모델로 확인했다. 동일 승인 ID/영수증/출력을 재사용하고 후속 편집은 버퍼에 유지했다.
- 요청자 또는 문서 owner의 결과 수신 중단과 600초 만료 표시를 추가했다. 실행 중인 HTTP/CLI가 물리적으로 즉시 중단된다고 주장하지 않는다. 늦은 결과 게시를 막고 이미 보관한 원문/후보를 보존한다. 서버 재시작 시 모델 작업을 자동 재실행하지 않는다.
- 실제 rhwp에서 굵게·가운데 정렬 제목, 본문, 2×2 표를 만들고 저장·다운로드·같은 문서 재업로드·재열기를 3회 반복했다. 표 XML·셀 내용/테두리·제목 서식과 과거 blob 해시를 비교했다. 최초 버전 복원은 새 8번째 버전을 만들었다. 한컴이 참여한 반복 왕복은 아니다.
- `scripts/test-isolated.ps1`은 새 폴더/DB/파일/포트/복사한 검증 엔진으로 일반·인증·로컬 시험을 실행한다. 소스와 별도 진단 앱 번들을 지원한다. 실제 모델 호출은 없고 자신이 만든 프로세스만 종료하며 증거를 보존한다.
- `scripts/audit-storage.py`는 SQLite 메모리 스냅샷과 blob을 읽어 참조·계보·크기·해시를 검사한다. 원본 DB나 파일을 수정/삭제하지 않는다. 기존 문서함의 문서 33개·버전/파일 55개가 통과했다. 백업/복구 자동화는 아니다.

## 실제 검증과 제한

- 변경 전: pytest 34개, 엔진 빌드 보호 11개, 인증 포함 기존 E2E 8개 통과.
- 변경 후: 최종 전체 pytest **136개 통과**, 기존 경고 1개, skip 없음. 실제 일반/작업 전용 MCP stdio 전송 시험과 Codex timeout 모델 이력 시험을 포함한다. 실제 모델 호출은 아니다.
- TypeScript와 엔진 빌드 보호 11개 통과. 사람 시험 하네스 고정 객체 시험과 구문 검사 통과.
- 전체 소스 E2E 20 passed / 장시간 opt-in 1 skipped. 진단 앱 번들 로컬 E2E 10 passed / 장시간 1 skipped. 이후 승인·영수증 응답 유실 추가 2개도 진단 번들에서 통과했다.
- 실제 엔진 유니코드/페이지 수 보호 추가 2개 통과: 한글+이모지 4,000 코드포인트의 페이지 수 유지 교체/undo, 페이지 수가 늘 때 거부·영수증 없음·원본 내보내기 바이트 복구. 짧은 문단의 무조건 확장이 가능하다는 최초 시험 가정은 실패했고, 엔진 보호를 유지한 채 시험과 안내를 바로잡았다. 전체 소스 20개와 이후 추가 4개는 서로 다른 일반 E2E 24개이며, 24개 전체를 한 번에 실행한 것으로 합치지 마라.
- 서버를 실제로 kill·재시작한 602.33초 시험: 모의 HTTP 호출 1회, 자동 재실행 없음, 버전 1개·원본 해시 유지, 600초 이후 만료 표시. 이 시험은 저장 fixture이며 실제 엔진은 사용하지 않았다.
- 실제 시계 장시간 시험 **1개 통과**: 비교/자동 저장 보류 3,600.191초, 60회 점검, 임대 갱신 120회 모두 성공, 버전 1개·원본·미저장 편집 유지. 이후 오래된 후보 차단 → 수동 저장 → 새 후보 저장 → 자동 저장 재개로 버전 4개를 확인했다. 브라우저 오류 0개다. 원시 증거의 `held_seconds=3617.703`은 마지막 저장 검사까지 포함하므로 보류 시간은 마지막 checkpoint를 사용한다. 이 1개도 실제 rhwp + 모의 모델 + 자동 클릭이다.
- 시험 서비스를 종료한 뒤 사용 포트 70개에서 리스너가 0개임을 확인했다. 기존 DB·파일 56개와 기준선·기존 인수인계를 합친 58개 파일의 SHA-256은 모두 시작 값과 같았고 `data` 아래 새 파일도 없었다. 시험 로그·DB는 분리된 `.cache`에 보존하고 실문서/DB를 변경 목록에 포함하지 않았다.
- 1시간 시험의 API를 종료한 뒤 합성 저장소를 별도로 감사했다. 문서 1개·버전/파일 4개·30,523바이트의 참조·계보·크기·해시 검사가 통과했고 참조 없는 파일도 없었다.
- 실제 엔진은 rhwp 0.8.6 / `e8800c8def63449808a4092798442652ed460552`의 기존 패치된 진단 빌드 복사본이다. WASM SHA-256은 `0e81cdeb4a61de8dd12be6d79d3bf06a8c1153525883e4112f4dcb1257d68195`이며 번들 6개 파일을 검사했다.
- 기본 `npm run build`는 기본 경로의 검증된 최적화 코어/번들 부재로 **가드가 거부**했다. 가드를 낮추거나 기본 엔진을 교체하지 않았다. 별도 진단 앱 빌드 통과를 Docker/nginx/최적화 배포 통과로 표현하지 않는다.
- 첫 실행기의 PowerShell 오류, 일반 API에 모의 모델 설정이 들어간 오류, Windows 테스트 worker 비정상 종료를 숨기지 않고 기록했다. 수정/재실행 결과는 별도로 남겼다.

실제 로컬 모델 서버 `127.0.0.1:1234/v1/models`는 연결되지 않았다. **이번 실제 모델 생성 0회·실제 사람 승인 0회**다. 모든 새 후보 E2E는 명시적인 모의 HTTP 모델과 자동 클릭이다. 이름·날짜·금액·부정 표현을 프롬프트에 보존 지시한 사실을 모델 품질 보장으로 해석하지 마라.

실제 사내 Qwen, “Qwen 3.8”의 정확한 모델 ID/규격, 인터넷 차단 환경, 새 한컴 반복 왕복, PostgreSQL/Compose 배포는 미검증이다. 기존 9/27 실제 Codex/사람/한컴 증거는 역사적 근거로 유지한다.

## 네가 답할 내용

1. 이 최소 설계가 기존 저장·권한·승인 불변 조건을 깨뜨릴 가능성이 있는 부분을 구체적으로 검토해 줘. 증거가 없는 결함을 확정하지 말고 확인할 코드/재현 조건을 구분해 줘.
2. 현 상태에서 바로 진행할 코드/시험과 실제 서버·사람이 있어야 하는 확인을 분리해 다음 우선순위를 정해 줘. 이미 끝난 모의/엔진 구현을 처음부터 다시 지시하지 마라.
3. 실모델 재개에 필요한 최소 동작은 준비된 서버 실행, 실제 `/models` ID와 인증 설정, 별도 합성 환경에서 사람 후보 클릭이다. 승인 전후 각 단계를 별도 증거로 남기는 간결한 지시를 만들어 줘.
4. 목적·확정 사실·대화를 두 후보 입력에 포함하는 확장이 필요하다면 컨텍스트/리비전 고정과 사실 출처 표시부터 설계해 줘. 단순 DB 보관을 독립 세션 복원 완료라고 부르지 마라.
5. Docker·유료 API·자동 대체·모델 다운로드·원본 변경·무단 커밋/푸시/병합 없이, 가장 실익이 큰 후속 작업을 제안해 줘. 원격 코드를 확인할 경우 로컬 미커밋 변경과 구분해 줘.
