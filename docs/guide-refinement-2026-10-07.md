# PDF 가이드 반영 및 목차·개조식 개선 검증

사용자 제공 PDF를 참고해 금융권 보고서를 새 산출물로 작성했다. 기준 HWPX, PDF 원본, 기존 보고서, 저장된 원본·과거 버전은 보존했다. HEAD는 `1e0538781e02ac85d095bb3c72bf844943c305b3`이며 기존 미커밋 작업 위의 수정이다. commit/push/merge, 엔진 교체, 모델 설치·실호출은 하지 않았다.

## 결과

- `reports/2026-10-07/guide-refined/financial-cyber-standard.hwpx` 및 같은 이름 PDF: 9쪽, 내용 표 5개, 그림 2개, 표지·목차용 표 2개.
- 목차는 기준서의 회색 상자·큰/작은 항목·native 리더 탭을 사용한다. 점 문자열을 없애고 본문의 동일 제목 ID를 참조한다. 9개 목차 항목을 실제 엔진의 본문 쪽수와 대조했다. 표지·목차를 포함하는 물리 쪽수로 본문 시작은 3쪽이다.
- 본문은 `추진 배경 및 개요 → 주요 내용 → 시사점 및 향후계획`, 개조식 8개 묶음(□ 8 / ㅇ 8 / - 8)으로 정리했다. `(요약)`, `(결정)`, `(차이점)`, `(통제)`, `(검증)`, `(추진)`, `(보호)`, `(범위)` 말머리를 사용했다.
- 본문 15pt·왼쪽 정렬·160%, 기호 위치 0/10/20pt, 내어쓰기와 ※ 맑은 고딕 13pt를 반영했다. 표지의 파란 상하선은 원본 값을 유지했다.
- `scripts/build-guide-report.py`는 기존 작성 도구를 재사용한다. 168개 텍스트 항목은 실제 rhwp의 문서·선택·preimage fences가 있는 exact command를 거쳤다. 배치 단계는 해당 출력 문단과 영수증 텍스트 해시를 확인한 뒤 재사용했다.
- `scripts/render-standard-report.mjs`의 재개 판단은 ID만이 아니라 텍스트 해시와 배치 출력 파일 존재를 확인한다. 실제 문장 1건 재수정 시 해당 20개 항목 배치를 다시 적용해 168개의 고유 영수증을 유지했다.

## 제품 및 설계 반영

공통 프로필 r3, 생성 지침 `korean-report-v2-outline`, 기호별 서식과 긴 문단 후속 조각의 스타일을 구현했다. 기존 승인 이후 텍스트를 자동 변환하지 않는다. `docs/document-writing-standard.md`와 AGENTS.md에 기본 규칙을 남겼다.

[템플릿 설계](report-template-design-2026-10-07.md)는 내용 트리·서식·배치 검증을 분리한다. 리비전/해시 고정, 제목 ID 기반 목차, 최대 3회 쪽수 수렴, 승인/저장 재시도, 템플릿 변경 충돌, 일반/상세 보고의 완료 기준을 정리했다. **범용 템플릿 선택·등록과 편집 후 자동 목차 갱신은 설계만 완료**했다. 현재 일반 보고서 UI에 표·그림·목차 자동 생성 기능이 생겼다는 의미가 아니다. 모델이 의미상 올바른 계층을 생성하는지도 이번 모의 시험만으로 보장하지 않는다.

## 저장과 보존

별도 사용자 검토 저장소에 새 문서 `7fefd91a-6dc2-4b87-abce-94e43508ce9b`, 확정 버전 `31ff2767-ba74-4c2b-a314-e5463d72a204`로 업로드했다. 서버에서 버전 파일을 다시 내려받아 원본 출력과 동일 바이트임을 확인했다. SHA-256: `decd7d74f77b716dd77c12ccdb9fbc4a8e3a800d944ff16effa12b8b010ac11b`. 기존 7개 문서의 current_version은 바뀌지 않았다.

수정 전 기록한 83개 파일 중 82개가 같은 해시다. 나머지 하나는 의도적으로 r3로 갱신한 `profile.json`이다. 기준 HWPX·사용자 PDF·기존 산출물·원본 및 과거 HWPX blob은 모두 보존됐다. DB·토큰·인증 파일·캐시 전체는 제공 산출물에 포함하지 않았다. 브라우저의 사용자 편집 버퍼를 열거나 새로고침하지 않았다.

현재 사용자 검토 서버는 같은 `http://127.0.0.1:15180/`에서 r3 소스를 사용한다. 실행 중 생성 작업이 없음을 확인하고 기존 서버가 소유한 프로세스만 종료한 뒤 새 진단 번들로 시작했다. 번들 JS는 `index-C4dPm7BN.js`, 실행 기록은 `.cache/user-review/runs/20261007-002207-ca725d88`이다.

## 남은 차이

rhwp에서 HWPX의 `KEEP_WORD` 값이 있어도 일부 한국어 어절이 글자 단위로 나뉜다. 기본 엔진은 바꾸지 않았다. PDF는 같은 엔진 배치를 반영하며 지정 글꼴 대체 가능성도 있다. 실제 한컴 재개방·글꼴/어절 나눔·인쇄 검수는 남아 있다.

가이드의 '문단 위 10cm'는 오기인지 확정하지 않고 자동 적용에서 제외했다. 기존 HWPX와 다른 제목 파랑 값도 원본 HWPX를 우선했다. PDF에 포함된 도구 설치·연락·Claude 스킬 등록 요청은 실행 지시로 취급하지 않았다.

이번 목차는 생성·검증 시점의 스냅샷이다. 사용자가 본문을 늘려 쪽수가 바뀌면 목차 재생성이 필요하다. 다음 최소 사용자 동작은 새 개선본을 열어 내용·한컴 최종 서식을 확인하는 것이다. 일반 UI를 새 코드로 다시 읽을 때는 미저장 편집을 먼저 저장한다.
