# AI 초안·검토 기능 설계

상태: 구현 전 기능 계약 초안. 최신 개발 우선순위는 **실제 LLM 호출부터 검증**이다.

## 1. 모델과 환경의 구분

개발은 기존 장비의 로컬 모델 또는 두 개발자가 공유하는 자체 모델 서버를 사용한다. Ollama는 개발 실행 후보이며 공유 호스트·접속 방식·개발 모델은 아직 확정되지 않았다.

운영에서는 사용자가 사내 배포 모델이라고 전달한 **“Qwen 3.8”**을 활용하는 방향이다. 이는 사용자 표현이며 공식 모델 ID·크기·양자화·API 규격은 확인 전이다. 개발 모델의 측정 결과를 사내 모델의 성능으로 소개하지 않는다. 내부 운영에 Ollama를 새로 설치해야 한다는 전제도 두지 않는다.

유료 OpenAI API는 사용하지 않는다. 프로토콜 호환 여부와 실제 호출 대상을 구분하고, 실패 시 유료 외부 API로 자동 전환하지 않는다.

## 2. 초안 생성 흐름

문서 유형·목적·독자·입력 사실 → 섹션별 초안 요청 → 출력 구조 검증 → 부족한 정보 표시 → 사용자 수정·승인 → 편집기 명령으로 적용.

사실 입력에는 확인된 이름·수치·금액·기한만 사용한다. 모델에게 없는 정보를 채우라고 요구하지 않고 `입력 필요` 또는 `확인 필요`로 반환하게 한다. 초안은 문서 전체 XML이나 임의 파일 경로가 아니라 섹션별 본문 제안이다.

## 3. 검토 흐름

선택 영역·최소 주변 맥락·기준 버전·원문 해시 → 검토 → 문제 위치·이유·수정안 표시 → 사용자가 제안별 승인 → 기준 버전과 원문 재검증 → 적용 → 새 HWPX 버전 저장.

원문이 바뀌었다면 제안을 자동 적용하지 않고 재검토한다. 철회·되돌리기 동선도 제공한다. 모델의 문장 개선 의견, 코드 검사 결과, 확인된 규정 근거를 서로 다른 유형으로 표시한다.

## 4. 규칙 검사와 문체 검토의 분리

| 검사 유형 | 방법 | 표시 원칙 |
|---|---|---|
| 형식·필수 항목 | 확정 규칙을 코드로 검사 | 사용한 규칙 ID·버전과 문제 위치 |
| 수치·합계 | 표 구조와 정의된 계산식을 코드로 검증 | 원값·계산식·불일치. 의미가 불명확하면 확인 요청 |
| 문체·중복·모호성 | LLM의 검토 제안 | 제안 이유·대안. 확정 오류처럼 단정하지 않음 |
| 사내 규정 | 승인된 원문과 규칙이 준비된 범위만 | 실제 근거 문서·조항·버전. 미확인 조항 생성 금지 |

규정 사진을 보관했다는 사실만으로 조문을 판독·검증했다고 간주하지 않는다. 이번 정리에서는 사진 원문을 분석하거나 규정 준수 규칙을 확정하지 않았다.

## 5. 제안 응답 계약 예시

아래 JSON은 인터페이스 설계 예시이며 실제 엔드포인트·라이브러리 사양이 아니다. 식별자와 예시 문장은 합성 값이다.

```json
{
  "request_id": "demo-request-001",
  "document_id": "demo-document",
  "base_version_id": "demo-version-3",
  "status": "needs_confirmation",
  "suggestions": [
    {
      "suggestion_id": "demo-suggestion-1",
      "target_id": "paragraph-7",
      "original_text_hash": "placeholder-not-a-real-hash",
      "category": "clarity",
      "reason": "완료 기한이 입력되지 않았습니다.",
      "proposed_text": "[완료 기한 입력 필요]까지 결과를 제출합니다.",
      "requires_user_confirmation": true
    }
  ],
  "missing_fields": ["완료 기한"]
}
```

실제 요청 식별자·대상·해시는 서버가 만든 값과 비교한다. 모델이 반환한 값을 신뢰하지 않는다. 허용된 필드·길이·유형을 검증하고, 비정상 JSON·대상 누락·과도한 출력은 적용하지 않는다.

## 6. 공급자 교체 경계

앱은 공통 `LlmProvider` 경계를 소유한다. 모델 ID·서버 주소·인증·시간 제한·문맥/출력 한도·프롬프트 버전은 설정으로 분리한다. 비밀값은 브라우저·저장소·로그에 포함하지 않는다.

최초 실제 호출, 초안/검토 정상 응답, 시간 초과·취소, 비정상 출력, 동시 요청, 공급자 변경을 같은 계약으로 시험한다. 재시도 횟수·대기열 한도·오류 표시 방식을 명시한다. 화면 테스트용 Replay/Mock은 실제 모델 호출과 구분해 표시한다.

## 7. 초기 평가 기록

| 항목 | 기록할 근거 |
|---|---|
| 실행 환경 | 실행일·모델 ID/버전·설정·하드웨어·프롬프트 버전 |
| 속도 | 최초 응답과 전체 완료 시간. 실제 호출 수와 동시성 |
| 출력 형식 | 전체 시도 중 스키마 통과·실패 건수 |
| 사실 보존 | 입력 외 이름·금액·날짜 생성 여부와 사례 |
| 검토 유용성 | 채택·수정 후 채택·거절 건수와 이유 |
| 안전한 적용 | 오래된 제안 차단, 비대상 내용 보존, 되돌리기 |

현재 실측 수치는 없다. 합성 예제의 결과와 실제 사내 문서 성과를 섞지 않는다.
