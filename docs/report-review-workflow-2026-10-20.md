# 보고서 검토 흐름과 원문 양식 · 2026-10-20

새 보고서는 **초안 작성 → 내용 검토·보완 → 서식·페이지 배치 → 편집·저장** 순서로 진행한다. 작성 화면에는 요청, 작성 목적, 서식 선택과 자료 검색 옵션을 먼저 둔다. 예시·기준·목록 새로고침은 접는 영역, 과거 요청은 별도 도구로 옮겼다. 사이드바의 펼침·아이콘·숨김 선택은 모든 화면에서 공유하며 단계 전환으로 바꾸지 않는다.

## 내용 검토와 보완

완료·검증된 `ReportDraft`의 요약, 본문, 표·흐름도, 출처와 확인 사항을 먼저 표시한다. `이 내용으로 문서 만들기`를 누르기 전에는 새 HWPX 미리보기를 준비하지 않는다. 이미 생성한 frozen preview는 기존 ID로 바로 복구한다. 처리 중 표시하는 내용 목록은 최종 HWPX 서식을 흉내 내지 않으며, 배치 검증 후 실제 rhwp 편집기를 표시한다.

보완은 `POST /api/report-tasks/{source_task_id}/revise`에 새 `id`, 검토한 `draft_sha256`, `feedback`을 전달한다. 서버는 소유자·완료 상태·SHA를 검사하고 기존 요청·서식·표지 입력과 검토 초안을 새 작업에 고정한다. 같은 요청 재확인은 모델을 다시 실행하지 않는다. 응답 유실과 새로고침에서도 같은 보완 요청을 복구하고, 일시적 조회 오류에서는 복구 포인터를 지우지 않는다.

보완 결과가 기존 출처 ID·주소·제목·날짜를 삭제하거나 바꾸면 완료 상태로 게시하지 않는다. 중요한 수치·조건·사실 보존은 생성 지시에 포함하지만 의미 보존 전체를 자동으로 증명하는 기능은 아니다. 검토 화면에서 확인해야 한다. 원래 작업·frozen preview·저장본은 그대로 남고 최근 목록에서 보완본을 구분한다. 열린 HWPX의 미저장 직접 편집을 보완 요청에 몰래 대체하거나 포함하지 않는다.

## 별첨 구성과 원문 차이 수정

- 별첨 1: 표지·목차 없이 본문 시작.
- 별첨 2: 표지, 별도 목차, 본문 순서.
- 별첨 3: 표지의 작성일과 부서 사이에 목차를 두고 본문 시작.

새 기본 본문은 원문 예시의 `□ → ㅇ → -`, 휴먼명조 14pt다. 이전에는 기호 본문을 번호로 바꾸면서 중제목 글꼴과 크기가 적용됐다. 번호 항목은 사용자가 선택하는 옵션으로 남기고 원문 기본과 분리했다. □ 앞 원문 공백은 실제 엔진에서 측정한 24.75pt의 문단 여백으로 옮겼다. [실측 근거](evidence/reference-bullet-indent-2026-10-20.json)를 보존한다.

새 별첨 1 계획은 첫 제목에 `title_layout: "reference-title-v1"`을 고정한다. 이 경로에서는 원문 별첨 1의 1셀 제목 표(기본 높이 15mm, 상하 파란 선, 가운데 정렬)와 바로 다음 빈 문단의 간격을 재사용한다. 선택한 제목 글꼴·행간·상자 높이·선 색과 두께를 반영하며, 제목 표와 뒤 간격이 차지하는 공간을 본문 페이지 계산에 포함한다. 일반 문단의 장식선이 첫 절 제목 위로 겹치던 문제를 실제 공간을 가진 표로 해결한다. 이 표시가 없는 기존 계획은 제목 문단을 표로 바꾸지 않는다. 이미 고정한 preview의 계획·배치·저장 재확인은 재생성하거나 새 표시를 덧붙이지 않고 보존한다.

새 별첨 2·3 요청에는 `cover: {date, department}`를 고정한다. 값이 없으면 빈 자리만 유지하며 기준서의 2015년 날짜나 예시 부서를 복사하지 않는다. 새 계획의 `reference-cover-v1` 표시는 원문 빈 문단과 제목 표를 재사용하는 배치 경로를 선택한다. 이 표시가 없는 기존 계획은 이전 배치 경로를 사용한다. 표지 문자도 fenced exact 명령에 포함하고, 표지 뒤에는 본문 페이지 계산을 새로 시작한다.

목차는 기존 제목 UUID·텍스트 해시와 최종 엔진 쪽수를 사용한다. 글자 축소, 제목 생략, 검증 한도 완화로 표지나 목차를 맞추지 않는다. 저장은 마지막 `초안 확정·서버 저장`에서 수행한다. 원본 기준서와 기존 문서·버전·등록 서식을 수정하지 않는다.

## 기존 문서의 서식 변환 검토

별첨 1 문서를 별첨 2로 바꾸는 기능은 아직 제공하지 않는다. 다음 작업은 선택한 **현재 HWPX 버전**을 입력으로 받아야 한다. 최초 AI 초안을 다시 생성하면 사용자가 고친 본문·표·주석을 잃을 수 있기 때문이다.

지원 구조를 먼저 식별하고 본문·표·그림·주석과 제목 연결을 보존한 별도 변환 미리보기를 만든다. 선택한 등록 표준의 리비전과 해시를 고정하고 표지·목차를 재배치한 뒤 실제 쪽수를 다시 측정한다. 지원하지 않는 개체는 조용히 제거하지 않고 변환 불가 항목을 보여준다. 승인 시 새 문서 또는 새 버전으로 저장하며 원본을 덮어쓰지 않는다. 문서 버전·편집 세션 검증, 후속 미저장 편집 보존, 저장 응답 유실 재확인은 기존 편집 계약을 재사용할 수 있다.

기술 시험, 실제 Codex 결과 검토, rhwp 렌더링과 Hancom 검수는 각각 구분해 기록한다.

## 확인한 결과

합성 업무 자료로 실제 Codex에서 별첨 1~3 초안과 의견 반영 1건을 생성했다. 완료된 세 초안을 별도 시험 저장소의 실제 rhwp에 적용해 서버 저장·일반 편집기 재열기를 확인했다. 별첨 1은 2쪽, 별첨 2는 표지 1쪽·목차 2쪽·본문 3쪽부터 총 4쪽, 별첨 3은 표지 목차 1쪽·본문 2쪽부터 총 3쪽이었다. 목차 항목은 모두 한 줄이며 2회에 수렴했다. 이 수치는 이번 샘플 관찰값이며 새 제한이 아니다.

원문 표 폭을 유지한 4열 표의 날짜·완료 증거는 여러 줄로 감기며, 별첨 3의 확인 사항은 마지막 쪽으로 이어진다. 전체 9쪽의 내용 잘림과 제목선 겹침은 발견하지 못했다. Hancom 2018 재검수와 실제 사람의 내용 승인은 수행하지 않았다. 입력·출력 해시, 실제 호출과 재생의 구분, 샘플 위치는 [모델·배치 검증 기록](evidence/reference-model-layout-2026-10-20.json)에 남겼다.

검토·보완 API 및 원문 표준 등록 관련 시험 56개, 제목·표지·rich·목차 회귀 69개를 각각 실행했다(중복 범위가 있어 합산하지 않는다). 보완 응답 유실 뒤 재접속·동일 요청 확인, 기존 frozen 등록본, 등록 응답 유실 재확인도 별도 E2E에서 통과했다. 전체 pytest/E2E나 배포 엔진 빌드를 반복한 결과로 표현하지 않는다.
