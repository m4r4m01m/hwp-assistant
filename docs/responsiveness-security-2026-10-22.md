# 홈서버 점검 후 반응성·보안·UI 개선

기준 소스는 main `4afb48d5aa65733b28a4ce4438dc4d371d8bdbe6`이다. 코드 검증, Docker 배포 검증, 실제 홈서버의 체감 시간은 구분한다. 구현 과정의 임시 작업 경로 초기화 후 소스를 복구하고 검증을 다시 실행했다. 서버 핵심 변경은 원격 체크포인트에서, 엔진 bridge와 일부 UI 회귀는 원래 바이트에서 복구했다. 다시 구성한 화면·배포 코드는 최종 소스로 회귀를 재실행하며 이전 통과 기록만으로 완료 판정을 하지 않는다.

## 1. 사용자가 체감하는 변경

| 동작 | 변경한 동작과 이유 |
|---|---|
| 첫 화면 | 보고서·양식 마켓·문서 표준 화면은 선택했을 때 불러와 초기 JS를 줄인다. |
| 문서 검색 | 300ms 입력 대기 후 조회하고 Enter로 즉시 검색한다. 이전 요청 취소와 응답 순서 검사로 오래된 결과가 최신 목록을 덮지 못하게 한다. |
| 문서 열기 | 편집 임대로 현재 버전을 확정한 뒤 해당 파일 다운로드와 편집기 준비를 병렬 실행한다. 취소된 작업의 늦은 완료는 편집기를 바꾸지 않는다. |
| 저장·업로드 | 진행 상태를 표시하고 중복 실행을 막는다. 응답 유실·시간 초과는 결과 불명으로 다루며 같은 입력·문서 ID·요청 키로 확인한다. |
| 편집 화면 | 문서명과 실제 저장 상태를 항상 보이게 한다. 작은 화면의 보조 패널에 충분한 폭을 주며 가려진 편집기는 미저장 내용을 유지한 채 입력만 막는다. |
| 버전 기록·공유 | 로딩을 빈 기록과 구분하고 재시도를 제공한다. 공유 창에 이름·초점 이동·Esc 닫기·이전 초점 복귀를 적용한다. |
| 양식 미리보기 | 첫 페이지부터 표시하고 후속 페이지를 순차 준비한다. 취소와 제한된 메모리 캐시를 제공한다. |
| 문서 비교 | 글꼴 14개를 미리 모두 다운로드하지 않는다. 같은 글꼴을 등록하고 native SVG가 쓰는 글꼴을 요청한 뒤 배치가 준비되면 표시한다. |
| AI 미설정 | 서버 미설정과 사용자 권한 부족을 실행 전에 안내한다. 기존 문서 편집·저장과 이미 생성한 초안의 검토는 계속 사용할 수 있다. |

양식 미리보기 캐시는 컴포넌트 메모리에서 최대 3개·8MiB·2분으로 제한한다. 문서·버전·파일 SHA-256과 엔진 build-info 해시를 확인한다. **캐시 재사용 전에도 파일을 새로 요청해 현재 권한과 바이트 해시를 검증**하므로 권한 회수 후 이전 미리보기를 캐시만으로 보여 주지 않는다.

문체 개선 polling은 패널이 열려 있고 브라우저가 보이며 작업이 실행 중일 때만 수행한다. 중첩 요청을 막고 실패 시 대기 시간을 늘린다. 보고서 조회도 화면 가시성·실패·변경 없는 결과에 맞춰 간격을 조절한다.

## 2. 서버와 정적 파일

- 업로드·저장의 HWPX 검사, 버전 비교, 해시·파일 쓰기·fsync 및 DB 처리를 worker thread에서 수행한다. DB Session도 해당 worker에서 만들고 닫는다. 원본·이력 불변성, 편집 임대·기준 버전·중복 저장 검사와 파일/DB 확정 후 저장 표시를 유지한다.
- 문서 목록은 문서와 사용자 권한을 한 SQL 조회로 가져온다. 검색어는 200자 이내로 제한한다.
- HTTP 모델 호출은 같은 API event loop의 연결 풀을 재사용한다. 별도 asyncio loop를 쓰는 background worker는 이 풀을 공유하지 않는다. 전체 시간·연결·풀 대기 제한을 두며 모델 POST를 자동 재시도하지 않는다.
- 모델 응답은 64KiB 단위로 읽고 누적 2MiB를 넘으면 중단한다. 초과 Content-Length는 본문을 읽기 전에 거절하고 timeout·취소 때 응답을 닫는다. 압축 디코더 순간 메모리까지 포함한 프로세스 메모리 상한을 뜻하지 않는다.
- API 응답에 생성한 `X-Request-ID`와 `Server-Timing`을 추가한다. JSON 로그는 경로 템플릿·상태·시간만 기록하며 토큰, 검색어, 문서 이름·내용, 전체 URL을 넣지 않는다. Server-Timing은 응답 헤더까지, 로그는 응답 처리 종료까지의 시간이다.
- 빌드 때 JS·CSS·WASM 등의 gzip을 생성한다. Nginx가 준비된 압축을 전달해 요청마다 홈서버가 압축하지 않는다. 원본 바이트는 변경하지 않는다.
- 성공한 해시 정적 파일만 1년 immutable로 캐시한다. HTML·로더·manifest·worker 진입점·버전 없는 글꼴은 재검증한다. API는 no-store 및 비압축이다. 캐시 규칙이 CSP·nosniff 헤더를 없애지 않도록 server 수준에서 함께 설정한다.

최종 소스로 두 Nginx 설정을 다시 검사했을 때 native 진단 kit의 실제 WASM은 **11,615,605 → 3,968,256바이트**로 줄었고 압축 해제 SHA-256이 일치했다. 65.84% 전송량 감소이며 네트워크·WASM 초기화·문서 파싱을 합친 홈서버 로딩 시간이 같은 비율로 감소한다는 뜻은 아니다. Vite 7.3.7 최종 진단 프런트엔드의 초기 app JS는 기존 배포 자산 413.56kB에서 **337.64kB**, gzip 기준 123.81kB에서 **103.54kB**로 줄었다. 보고서·양식 마켓·문서 표준 화면은 별도 청크로 필요할 때 로드한다.

## 3. 인증과 보안

### 브라우저 세션

정적 로그인 토큰을 그대로 쿠키에 보관하지 않는다. 로그인마다 임의 세션을 발급하고 DB에는 세션 해시만 보관한다. 기본 절대 만료는 8시간, API 사용이 없는 유휴 만료는 30분, 사용자당 활성 세션은 20개다. 로그아웃·재로그인·로그인 토큰 교체·사용자 제거 후 기존 세션을 사용할 수 없다.

명시적 Bearer 자동화 인증은 기존 계약을 유지한다. 로그인 세션과 120초 문서 편집 임대는 별개다. **배포 후 이전 브라우저 쿠키로는 한 번 다시 로그인해야 한다.** 세션과 AI 예약 테이블은 기존 문서 테이블을 삭제하지 않는 추가 스키마다.

인증 여부는 Host에서 만든 URL 대신 ASGI 경로로 판정한다. 공개 경로는 메서드까지 제한하고 중복·잘못된 Host와 허용 목록 밖 Host를 거부한다. 잘못된 Unicode 로그인 입력도 토큰을 오류 응답에 넣지 않고 거절한다.

로그인 실패는 클라이언트당 60초 내 20회로 제한하며 Retry-After를 제공한다. 이는 **현재 단일 API worker의 보조 방어**다. ASGI 클라이언트 주소는 Funnel → 호스트 Nginx → 컨테이너 Nginx → Uvicorn 전달 헤더 정화에 의존한다. 실제 ingress에서 사용자 제공 X-Forwarded-For를 위조 주소로 채택하지 않는지 확인해야 한다. 모든 요청이 프록시 주소로 보이면 사용자들이 제한을 공유한다. 다중 worker에는 공유 제한 저장소가 필요하다.

### 의존성과 배포

FastAPI/Starlette는 `0.136.3`/`1.3.1`, Vite는 `7.3.7`, Nginx는 `1.30.6-alpine`, PostgreSQL은 `17.11-alpine`로 맞추고 확인한 이미지 digest를 고정했다. 전체 의존성에 알려진 취약점이 전혀 없다는 판정은 아니다.

첫 PR CI의 참고용 npm audit에서 Vite 7.3.6 관련 경고가 확인되어 공식 수정 버전 7.3.7로 정확히 고정했다. [Windows editor 실행 관련 권고](https://github.com/vitejs/launch-editor/security/advisories/GHSA-587h-7wmj-h5pm)와 [개발 서버 파일 허용 경계 권고](https://github.com/vitejs/vite/security/advisories/GHSA-rq7h-c2jc-7f22)에 해당한다. 운영 프런트엔드는 Nginx 정적 제공이므로 이를 운영 Vite 서버의 취약점으로 해석하지 않는다. 수정 후 로컬 npm audit의 알려진 권고는 총 0개였으며, 실제 Vite 빌드와 UI·native 엔진 브라우저 회귀를 다시 검사한다. 이 결과는 당시 npm 의존성 권고 데이터에 대한 검사이며 전체 서비스 보안 인증은 아니다.

배포 스크립트는 기존 DB 컨테이너를 교체하기 전에 앱 쓰기를 멈추고 기존 DB와 문서 파일을 일관된 세트로 백업한다. 백업 실패 시 기존 앱을 재개하고 교체를 중단한다. 백업 후 DB 교체 실패 시 쓰기를 중단한 상태에서 명시적 복구를 요구하고 자동 DB downgrade를 시도하지 않는다.

## 4. LLM 연결 준비

`GET /api/capabilities`는 로그인 후 기능별 configured·reachable·allowed·reason_code·message·supports_stream을 반환한다. 외부 모델이나 Codex를 호출하지 않는 설정 검사다. 설정이 있다는 이유로 연결 성공을 표시하지 않으며 reachable은 null이다.

HTTP 대화·검토·문체 개선은 `HWP_LLM_ALLOWED_USERS`로 사용자를 제한할 수 있다. 빈 값은 기존 로그인 사용자 허용 정책을 유지하므로 **guest가 있는 기존 서버에서는 모델 연결 전 명시적으로 설정**해야 한다. 새 환경 초기화는 생성한 owner만 허용한다.

즉시 실행 HTTP 모델 요청은 사용자당 동시 1개·기본 분당 20개이며 기존 문체 개선·보고서 작업과 서버 실행 용량을 공유한다. 모델 토큰 단위 금액 한도나 분산 작업 큐는 아니다. 대화 실행 예약을 DB에 남겨 재시작·동시 요청에서도 같은 질문의 모델 호출을 반복하지 않는다. 완료된 답변은 모델 호출 없이 반환한다. 이전 결과가 불명확하면 대화를 확인하고 새 질문으로 요청하도록 안내한다.

기존 유료 OpenAI 호스트 차단 정책은 유지한다. 보고서 생성·보완은 Codex app-server 경로이므로 LLM 환경변수만으로 외부 HTTP 모델로 전환되지 않는다. 실제 제공자·모델·API 키를 선택하거나 설정하지 않았고 실제 외부 모델 호출도 하지 않았다.

1. 제공자·모델·문서 전송 범위·비용 한도를 정한다.
2. API 키를 서버 비밀값으로 주입하고 허용 사용자를 지정한다.
3. 구조화된 후보 검증, 응답 지연·실패·중복 요청과 한국어 문서 품질을 확인한다.
4. 보고서에도 같은 제공자를 쓰려면 별도 adapter를 구현한다. 완결된 초안 검증, 사람의 검토와 명시적 저장 계약을 유지한다.

## 5. 블록 삽입 보호와 남은 엔진 문제

실제 고정 WASM에서 빈 문서 작성 후 HWPX export/import만으로 첫 문단의 줄 배치가 달라지는 경우를 재현했다. 이번 변경은 parser의 문자 위치 규칙을 추정해 바꾸지 않는다.

블록 적용 전 기존 본문의 텍스트, 줄 경계와 가로 글자 배치를 확인해 달라지면 원래 편집기를 유지한다. 정상 페이지 이동은 허용한다. 비용 한도와 표·글상자 등 제외 범위는 [블록 배치 보호 설명](block-layout-guard.md)에 기록했다.

**일반 HWPX export/import의 근본 결함을 해결한 것은 아니다.** 근본 수정에는 서로 다른 문서 형식의 문자 위치 규칙과 실제 Hancom 왕복 검증이 필요하다.

## 6. 검증과 운영 반영

```sh
.venv/bin/python -m pytest -q
.venv/bin/python scripts/deploy/test_deployment.py
.venv/bin/python scripts/developer-download.test.py
cd frontend
npm ci --no-audit --fund=false
npm exec tsc -- --noEmit
npm run test:unit
npx playwright install chromium
npm run test:ui
```

복구·통합 후 전체 Python 686개, 프런트엔드 단위 18개, Mock UI 10개, Node 정적/엔진/실제 Vite 경로 회귀 52개, 배포 도구 12개, 개발 kit 다운로드 사전검사 6개가 통과했다. 실제 Chromium과 native 엔진의 블록 삽입 4개·왕복 저장 1개·편집 화면 2개·양식 3개·문서 비교 6개도 통과했다. TypeScript 검사와 최종 native 진단 프런트엔드 빌드도 통과했다. Nginx 1.30.6의 실제 응답 42개에서 압축·캐시·보안 헤더 등 266개 조건을 재검증했다. 마지막 의존성 수정 후 재실행 결과와 최종 head의 CI는 PR 본문에 기록한다.

`test:ui`는 Mock API/Mock editor를 사용하는 로그인·검색·모바일·미리보기·polling 회귀다. 실제 엔진의 provenance나 렌더링·저장 검증을 대체하지 않는다. 실제 Chromium과 native 진단 엔진의 저장·비교·블록 삽입은 별도로 검사한다. 모델 모의 응답을 실제 LLM 검증으로 계산하지 않는다.

| 설정 | 기본값 / 영향 |
|---|---|
| HWP_ALLOWED_HOSTS | 실제 공개 호스트와 localhost/127.0.0.1/[::1]. URL·경로·포트는 넣지 않는다. |
| HWP_AUTH_SESSION_TTL_SECONDS | 28800. 로그인 절대 만료. |
| HWP_AUTH_SESSION_IDLE_SECONDS | 1800. API 사용이 없는 세션 만료. |
| HWP_AUTH_SESSION_MAX_PER_USER | 20. 오래된 활성 세션부터 폐기. |
| HWP_AI_REQUESTS_PER_MINUTE | 20. 즉시 실행 HTTP 모델 요청의 사용자별 제한. |
| HWP_LLM_ALLOWED_USERS | 기존 env에서 빠지면 기존 정책 유지. 모델 연결 전 owner 등으로 지정. |

Docker 최적화 WASM·PostgreSQL·HTTPS 통합 검증은 main의 `HWP deployment` 수동 workflow에서 수행한다. 코드 PR 통과만으로 운영 검증이나 배포가 완료됐다고 표시하지 않는다. 배포 절차는 [runbook](deployment-runbook.md)을 따른다.

공개된 2026-10-18 개발 kit는 새 bridge와 맞지 않는다. 새 release 자산 게시와 lock 갱신 전 기본 Windows 원클릭 다운로드는 명확한 오류로 중단한다. [개발자 빠른 시작](developer-quickstart.md)의 source build 또는 새로 제공한 진단 ZIP 수동 설치를 사용한다. ZIP SHA-256은 `a42347f367a2f63ca3833002aeba913f4b2c1b1e44f1ba7aed1ceed615fad160`이며 native Linux 진단 빌드, wasm_opt=false다. Docker production 및 Windows 실행 검증 완료를 뜻하지 않는다.

운영 반영 후에는 첫 로그인, 저장·재열기·이전 버전, 모바일 패널, gzip/cache, 폐기 세션 거부, 실제 ingress 주소 처리를 확인하고 홈서버 지연을 다시 측정한다. 전용 hostname으로 다른 앱과 origin 분리, DB 런타임 최소 권한, CPU·메모리 제한 실측, 외부 장치 백업·복원 훈련, 백그라운드 작업 영속 큐는 후속 과제다.
