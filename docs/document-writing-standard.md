# 기본 문서 작성 기준

## 2026-10-20 — 원문 기준으로 새 문서 표준 구성

사용자의 원문 기반 검수 요청에 따라 **새 문서 표준 revision 3은 이 절을 우선**한다. 아래 2026-10-07~18의 추가 서식은 이전 요청·revision 1/2·동결 초안의 재현 기준으로 보존한다. 새 기본값에 15pt 왼쪽 정렬, 파란 표, 별도 핵심 요약, 괄호 요약 말머리를 섞지 않는다. 기준 HWPX와 기존 `profile.json`, 원본·과거 문서, 기존 템플릿은 변경하지 않는다.

기준은 해시가 고정된 `backend/app/assets/document-standard/reference.hwpx`의 앞부분 「문서작성 표준」과 별첨 예시다. 명시된 규격이 예시 XML의 우연한 서식과 다르면 명시 규격을 우선한다. API의 `source`와 `rules`는 원문 위치, 예시 값, 적용한 규정과 차이를 제공한다. 문단 ID가 중복되는 원문이므로 위치는 XML 경로와 순번으로 기록한다.

- A4 세로, 위·좌·우 20mm, 아래·머리말·꼬리말 10mm. 본문 휴먼명조 14pt·양쪽 정렬·160%, 참고·주석 12pt·130%를 기본으로 한다.
- 제목 단계, 본문, 기호/번호 단계, 표 제목·단위·내용·출처, 표지 제목·작성일·부서, 목차 큰/작은 항목, 붙임 제목의 글꼴·크기·장평·자간·강조·정렬·줄간격·문단 간격·들여쓰기를 구분한다. 별도 예시가 없는 깊은 번호 단계와 기호는 본문 서식을 상속하며 출처 정보에 명시한다.
- 표는 가운데 정렬·110%, 회색 첫 행·검은 선·좌우 바깥선 없음, 최소 높이 7mm, 좌우 여백 1.8mm·상하 0.5mm를 기본으로 한다. 표 폭은 원문 예시의 실제 비율을 초기값으로 사용한다. 제목의 파란 상하선·높이, 표지 틀, 목차 상자와 여백도 편집한다.
- 번호·기호와 `*`, `**` 또는 `주1)`, `주2)` 주석 표식을 선택한다. 새 초안의 canonical 출처 ID와 사실은 유지하고, 선택한 표식과 윗첨자는 미리보기 계획을 고정하기 전에 적용한다. 숫자·날짜·시간·문장부호 규정은 새 작성 지시에 전달하며 기존 사실을 사후 치환하지 않는다. 괄호 말머리 OFF가 번호 `(1)`나 사실·조건을 지우지 않는다.
- 쪽번호는 실제 필드를 사용한다. 원문에는 전용 쪽번호 글꼴·크기가 없으므로 문자식 쪽번호는 출처 서식을 상속한다. 이를 원문에서 추출한 전용 규격으로 표시하지 않는다.

기본 프리셋은 원문 **별첨 1(표지·목차 없음), 별첨 2(표지와 목차 분리), 별첨 3(표지 안 목차)**다. 왼쪽 설정을 바꾸면 오른쪽 실제 rhwp 예시를 다시 렌더링하며, 등록은 해당 설정과 확인한 예시 해시를 함께 고정한다. 프리셋만 바꿀 때는 사용자가 편집한 나머지 값을 유지하고, 원문 기본값 복원은 별도 동작이다. 예시는 원문 별첨의 실제 내용을 사용한다. 번호와 주석은 원문에서 확인한 연결만 선택값에 맞게 표시하며 원문 전체 보기의 문구는 그대로 보존한다. 예시의 2015년 날짜·부서·업무 사실을 새 보고서 내용으로 복사하지 않는다.

보고서 화면의 **문서작성 기준 열기**는 문서 표준 메뉴로 연결한다. 원본/사본을 나눈 다운로드 버튼은 제공하지 않는다. 앱 내부 원문 보기는 `none` 채움값과 프레젠테이션 배경 메타데이터만 표시용으로 정리하며, 원본 파일은 그대로 유지한다. 새 예시에는 기존 문서의 저장된 줄 배치 캐시를 사용하지 않는다.

새 보고서는 [내용 검토·보완 단계](report-review-workflow-2026-10-20.md)를 거친다. 원문 기본 본문은 □·ㅇ·- 기호와 14pt이며 번호 항목 구성은 선택 옵션이다. 별첨 2·3의 작성일·부서는 사용자가 입력한 값만 표시하고, 새 표지 배치는 원문의 빈 문단 간격과 제목 표를 재사용한다.

기술 시험, 실제 rhwp 확인, 실제 모델 문구 확인, Hancom 검수는 별개다. 기준서 전체를 읽고 편집 항목으로 제공하더라도 모델이 모든 작성 규정을 항상 지킨다는 보장은 아니다. 자동 목차가 있는 프리셋은 기존 제목 UUID·텍스트 해시·실제 쪽수·명시적 갱신 계약을 사용한다.

## 2026-10-18 추가 — 표·제목 위치·표시 구성 선택

**문서 표준 편집**의 새 등록(revision 2)은 표 안 가로/세로 정렬·선 종류/지원 두께/적용 범위·셀 여백, 대제목의 파란선 안 세로 위치, 항목 요약 말머리·핵심 요약 표시, 쪽번호 형식/위치와 출처 표식을 선택한다. 선택한 표시 구성은 새 보고서의 fenced 계획을 만들기 전에 반영하며 원래 초안·기존 등록·frozen preview에는 소급 적용하지 않는다.

말머리 OFF는 항목 앞 괄호 말머리만 숨기고 일반 괄호·조건은 유지한다. 핵심 요약 OFF는 별도 요약 절과 요약 내용을 표시하지 않으며 원래 초안은 보존한다. 쪽번호는 실제 필드를 사용하고 출처 표식은 본문과 출처 목록에서 같은 ID를 유지한다. 기본 제목 위치 12pt는 기존의 위로 치우친 배치를 보정하며 파란 상하선은 유지한다. 이전 revision 1의 23필드·해시는 그대로 지원한다. 사용 범위·검증은 [표준 편집 확장](visual-standard-controls-2026-10-18.md)을 따른다.

## 2026-10-18 보완 — 등록한 시각 서식 선택

문서 목록의 **문서 표준 편집**에서 제목·본문·출처의 글자 크기, 줄 간격, 문단 뒤 간격, 계층 들여쓰기, 쪽 여백, 표 머리글 채움색·테두리 색을 바꾸고 실제 rhwp 예시를 확인할 수 있다. 최신 예시가 모두 표시된 뒤 **표준 템플릿으로 등록**하면 별도의 불변 서식으로 보관한다. 기존 원본 기준 HWPX와 `profile.json`은 수정하지 않는다.

새 보고서는 기존 세 작성 목적 프로필과 별도로 **문서 서식 표준**을 선택한다. 등록 서식을 선택하면 이 절에서 허용한 시각 값만 새 요청·스캐폴드·미리보기·승인에 고정한다. 선택하지 않으면 기존 기본값을 사용한다. 사실·출처·간결한 절 제목·□ → ㅇ → - 의미 계층과 파란 제목 상하선은 공통 기준을 유지한다. 기존 문서·과거 버전·이미 준비하거나 승인한 초안에 서식을 소급 적용하지 않는다.

등록 예시는 고정 합성 문구이며 모델 생성 보고서가 아니다. 표준 등록은 보고서의 확정·서버 저장과 별개다. 목차 UUID·실제 쪽수 측정·명시적 갱신·저장 재확인 경계도 유지한다. 사용법과 검증 범위는 [문서 표준 편집 구현 기록](visual-standards-2026-10-18.md)에 있다.

## 2026-10-17 보완 — 새 업무용 보고서의 절 제목

새 `ReportDraft`를 작성할 때 본문 절 제목은 하나의 핵심 논점을 드러내는 짧은 표제로 쓴다. 대상·쟁점·조치 중 필요한 요소를 담고, 같은 수준의 제목은 표현 방식을 맞춘다. 구별에 필요한 기간·대상·범위는 제목에 남긴다. `검토`, `기타`, `향후`처럼 단독으로는 내용을 구별하기 어려운 제목은 피한다.

배경 설명, 목적의 반복, 세부 조건과 사례 나열은 해당 절의 첫 본문 항목으로 옮긴다. 이때 중요한 사실·수치·기간·조건·인용을 삭제하거나 새로 만들지 않는다. 기본 서식의 목차 한 줄을 목표로 하되 필요한 명칭은 두 줄을 허용한다. 이는 작성 목표이며 글자 수 제한이 아니다. 문자열 자르기·말줄임표·글꼴 축소·목차 항목 생략으로 맞추지 않는다.

세 프로필 모두 이 공통 기준을 사용한다. 예를 들어 표준 업무보고는 `정비 필요성 → 수집 현황 → 정비 방안 → 추진 일정`, 의사결정 보고는 `검토 쟁점 → 대안 비교 → 권고안 → 승인 요청 사항`, 대응 계획은 `대응 목표 → 우선 조치 → 역할과 일정 → 완료 기준`처럼 실제 내용에 맞는 흐름을 구성한다. 이 문구를 고정 목록으로 강제하거나 앱이 추가하는 공통 요약·출처 항목을 별도 절로 반복하지 않는다.

다음은 가상의 작성 예시다. 짧아진 제목에서 빠진 설명과 조건은 첫 본문 항목에 보존한다.

| 긴 제목 | 간결한 본문 제목 | 첫 본문 항목 |
|---|---|---|
| 2026년 4분기 협력사 자료의 누락 항목과 보완 조건을 확인하고 매주 금요일 15시 공유를 준비하기 위한 수집 현황 | 2026년 4분기 자료 수집 현황 | □ (확인 범위) 협력사 자료의 누락 항목과 보완 조건을 확인하고, 매주 금요일 15시 공유에 필요한 수집 상태를 정리할 필요가 있음. |
| 지연된 제출 건은 담당자가 확인한 뒤에만 운영팀이 재공유하도록 하는 책임 구분과 승인 요청 사항 | 지연 자료 재공유 승인 요청 | □ (승인 조건) 지연된 제출 건은 담당자 확인을 마친 경우에만 운영팀이 재공유하도록 책임 구분과 처리 조건의 승인을 요청함. |

목차는 이 본문 제목을 기존 UUID·원문 텍스트 해시 연결 경로로 사용하며, 실제 엔진의 제목 쪽수 검증과 명시적 갱신 계약을 유지한다. 목차 전용 표제나 별도 생성 호출을 추가하지 않는다. 이 기준은 새 초안 작성 단계에만 적용하며, 생성된 HWPX·승인본·동결된 preview를 사후 재작성하지 않는다. 기존 긴 제목·20쪽 경계시험과 과거 증거도 그대로 보존한다.

## 2026-10-07 추가 요청 — 짧은 항목과 보이는 작성 과정

새 초안의 □ 항목은 표준 15pt에서 대략 2~3줄을 목표로 한다. 한 항목에는 한 논점만 담고 더 길면 별도의 □ 항목으로 나눈다. 생성 계약 `korean-report-v3-short-items`는 60~85자 안팎의 항목과 절당 최대 9개 문단을 허용하며, □·ㅇ·-를 무조건 한 세트로만 쓰도록 하던 지침을 제거했다. 출처·사실·조건을 삭제해 분량을 맞추지 않는다.

새 임시 미리보기 계획을 만들 때 `report_outline.py`가 긴 기호 항목을 동일 기호의 별도 문단으로 나눈다. 문장 끝, 어절 경계를 우선하고 본문 문자·공백은 그대로 보존한다. □가 길면 □를 추가하며, ㅇ·-의 보조 설명은 같은 계층으로 나눈다. 기존 draft JSON, 이미 고정한 preview 계획, 승인본, 원본·과거 blob에는 소급 적용하지 않는다. 최종 편집기 줄 수는 글꼴과 직접 편집에 따라 달라질 수 있다.

작성 화면은 실제 상태에 맞춰 `내용 작성 → 문서에 입력 → 서식·페이지 배치 → 편집 가능`을 표시한다. Codex 응답 전에는 작성 상태와 경과 시간만 표시하고 미확정 내용을 지어내지 않는다. 응답 이후에는 exact command가 성공한 문단만 진행 화면에 누적하고, 배치 완료 후 실제 rhwp 편집기로 전환한다. 진행 화면의 서식 미리보기는 최종 페이지 배치가 아니다. '작성 과정 천천히 보기'는 완료된 문단의 표시 간격만 조절하며 모델 속도·진행률을 흉내 내지 않는다.

같은 탭에서 보고서 화면에 다시 들어오면 최근 작업 ID로 현재 서버 상태를 조회한다. 미확정 초안은 고정된 한글 미리보기를 복구한다. 이미 저장된 경우에는 새 요청 입력을 허용하고, 최근 목록에서 해당 작업을 선택하면 실제 저장 문서 편집기로 연다. 미확정 직접 편집 내용을 새로고침 후 복구한다고 보장하지 않는다.

## 2026-10-07 추가 보완 — 편집 가능한 한글 초안

새 생성 요청은 텍스트 목록 대신 실제 rhwp 편집기에 서식이 적용된 임시 초안을 표시한다. 새 임시 스캐폴드에 fenced exact commands로 내용을 적용하고 영수증을 검증한 뒤, 동일 텍스트의 배치만 정리한다. 직접 편집한 문서는 `초안 확정·서버 저장`을 눌러야 문서 목록에 새 문서로 저장된다. 기존 문서를 자동 교체하거나 승인을 대신 클릭하지 않는다.

`backend/app/report_layout.py`는 과거 문단을 그대로 유지하면서 긴 제목을 어절 경계에서 균형 있게 나누고, 모든 절의 강제 새 쪽 시작을 제거한다. 실제 지정 글자 크기와 줄 수를 바탕으로 페이지 여유를 계산하며 제목과 첫 문단을 함께 배치한다. 현재 엔진에서 자동 어절 줄나눔과 적용 직후 줄 배치 캐시가 불완전하므로, 기존 텍스트의 공백을 보존한 **문단 안 줄바꿈**을 넣고 줄 배치 캐시를 새로 계산한다. 텍스트·기호·출처는 바꾸지 않는다. 글자 크기를 줄이거나 내용을 자동 축약하지 않는다.

초안의 직접 편집은 아직 일반 문서의 자동 저장이 아니다. 명시적으로 확정하기 전에는 '미저장'으로 표시하고, 준비 중·저장 결과 미확인 중에는 편집/작업 전환을 막는다. 저장 이후 '보고서 편집하기'는 기존 일반 편집·저장 흐름으로 연결한다. 목차·표·그림을 만드는 범용 템플릿 엔진과 편집 후 자동 재배치는 여전히 후속 작업이다. 이 추가 보완이 아래 이전 구현 기록의 텍스트 전용 초안 설명보다 우선한다.

- □에는 필요할 때 `(요약)`, `(배경)`, `(차이점)`, `(조치)`, `(제안)` 같은 짧은 말머리를 둔다. 모든 □에 `(요약)`을 반복하거나 확인되지 않은 판단을 사실로 만들지 않는다.

- ※ 주석은 가이드의 맑은 고딕 13pt를 사용한다. 기존 출처·표 내용 12pt, 파란 제목선·A4 여백·표지·표의 규칙은 기준서 값을 유지한다.
- 문장은 한 항목에 한 논점, 가능한 1.5~2줄로 정리한다. `~함/~임/필요` 등 개조식 종결을 쓰되 주체·행동 관계를 남긴다. 사실·분석·향후 제안을 구분한다. 근거 없는 숫자로 '급증' 같은 표현을 대체하지 않는다.

## 구현 범위

이번 금융권 보고서는 `scripts/build-standard-report.py`와 `scripts/render-standard-report.mjs`의 독립적인 산출물 작성 절차로 만들었다. 승인된 내용은 새 빈 스캐폴드에 rhwp exact commands로 적용했고, 그 출력 문단을 이용해 표지·표·목차를 배치했다. 기존 문서나 사용자 편집 버퍼를 대상으로 실행하지 않았다.

`/api/report-tasks`에서 새 초안을 승인하면 이제 이 기준서에서 추출한 서식을 자동 적용한다. 별도 표지 없는 보고서 제목의 파란 상하선, 휴먼명조 14pt 본문, HY헤드라인M 제목, 160% 줄간격, 항목 들여쓰기, A4 여백과 쪽번호를 적용한다. 긴 문단은 텍스트를 보존하면서 나누고 표준 글자 크기에 맞춰 페이지를 미리 배정한다. 실제 텍스트 적용은 기존 rhwp exact commands와 영수증 검증을 그대로 거친다. 자동 표·이미지 작성이나 자동 목차 생성까지 구현한 것은 아니다.

승인에 기준 ID·원본 해시·설정 해시를 고정하고 저장된 스캐폴드의 서식과 실제 출력을 대조한다. 이전에 승인한 작업은 현재 기준으로 몰래 재작성하지 않는다. 기준 파일이 없거나 원본 해시가 다르면 다른 서식으로 대체하지 않고 새 승인을 중단한다. 생성 화면의 ‘기준서 원본 보기’ 링크와 `/api/document-standard`에서 기준을 확인할 수 있다.
