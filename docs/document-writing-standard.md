# 기본 문서 작성 기준

## 2026-10-27 — 간결한 보고 문장과 실제 논점 요약어

새 보고서 작성 화면은 요청 내용·대제목 구성·문서 양식으로 정리한다. 별도 작성 목적 선택은 없애고 서버의 기본 작성 프로필을 새 요청에 고정한다. 과거 요청의 프로필·해시와 보완 초안의 상속 계약은 유지한다.

새 초안의 기호 항목은 **1~2줄 내외**를 목표로 한다. 아래 날짜의 2~3줄 목표보다 이 지침을 우선한다. 먼저 군더더기를 덜고도 길면 의미가 완결되는 문장·절 단위로 나누어 같은 수준의 기호를 이어 쓴다. 긴 □를 단순히 짧게 보이게 하려고 ㅇ나 -로 내리지 않는다. 근거·조건·담당 주체가 종속될 때만 하위 항목으로 둔다. 줄 수는 작성 목표이며 문자열 자르기나 강제 개행, 사실·기간·조건·인용 삭제로 맞추지 않는다. 기존 절·문단 한도도 유지한다.

괄호 요약어는 해당 항목의 논점을 약 5자 안팎으로 표현한다. `(패치현황)`, `(영향범위)`, `(접근제한)`처럼 실제 내용을 요약하고, 서로 다른 항목에 `(제안)`이나 `(핵심)`을 반복하지 않는다. 사실과 제안은 본문 문장으로 구별한다. 표시를 허용한 역할에서만 사용하며 구별에 도움이 없으면 생략한다.

새 생성 계약 `korean-report-v5-declared-leads`는 `lead_summaries`에 요약어와 정확한 본문 위치를 선언한다. 표시 OFF에서는 선언된 표제만 제거하고 `(승인 후)`와 같은 실제 조건·수치·인용 괄호는 보존한다. 새 표제는 번호형 본문에서도 굵게 표시한다. 필드가 없는 과거 초안·기존 해시·동결 미리보기는 이전 계약을 유지한다.

별도 모델 호출이나 생성 후 정규식 교정을 추가하지 않는다. 같은 생성 응답의 JSON 완료 전에 전체 초안을 훑어 보고체, 짧은 동급 항목, 구체적 요약어와 사실·출처 보존을 점검한다. 이는 작성 지시와 계약 검증이며 실제 모델이 항상 1~2줄을 지킨다는 보장은 아니다.

## 2026-10-26 — 선택한 대제목 구성과 절 안의 주석 정리

새 보고서의 **작성 목적**, **대제목 구성**, **문서 양식**을 구분한다. 대제목 구성은 내용의 순서이며, 상황·대응 보고는 `개요 → 현황 → 대응 → 향후 계획`, 의사결정 보고는 `검토 배경 → 대안 비교 → 권고안 → 승인 요청 사항`을 시작점으로 제공한다. 사용자가 3~6개 제목의 문구와 순서를 직접 바꿀 수 있다. 번호는 서식이 붙인다. 자동 구성을 선택하면 종전처럼 내용에 맞게 작성하며 별도 구성 필드를 추가하지 않는다.

선택한 `section_outline`은 새 요청의 입력·해시에 고정하고 검토 의견으로 만드는 후속 초안에도 상속한다. 모델은 지정한 제목·순서에 맞춰 내용을 작성하고, 완료된 ReportDraft의 제목·개수·순서가 다르면 미리보기로 보내지 않는다. 개요에는 핵심 판단, 현황에는 확인된 상태와 미확인 범위, 대응에는 완료·진행 중 조치와 제안의 구분, 향후 계획에는 제안과 확인 기준을 담는다. 근거 없는 담당자·일정·완료를 만들어 넣지 않는다. 문서 양식이나 이미 동결한 초안의 제목을 사후에 바꾸지 않는다.

아래의 초기 `reference-note-groups-v1`에서 □마다 같은 설명이 다시 나오는 문제를 줄이기 위해 **새 reference 계획은 `reference-note-section-groups-v2`를 사용한다**. 같은 제목 아래 이어지는 문단 내용은 여러 □를 포함해 하나의 주석 범위로 묶고 동일 출처 설명을 끝에 한 번 둔다. 문단 구분·표·도식에서 범위를 새로 시작하며 서로 다른 절의 근거를 문서 끝 한곳으로 옮기지 않는다. 본문의 각 인용 위치와 출처 ID·윗첨자 연결은 유지한다. 표의 공통 출처 표시, 출처 제목만 인쇄하는 정책과 이전 정책의 동결 미리보기는 보존한다.

## 2026-10-26 — 경영진 보고의 내용 우선 원칙

새 초안은 사용자가 다른 독자를 지정하지 않은 경우 경영진 보고를 기준으로 작성한다. 질문에 대한 답·핵심 판단과 업무상 의미를 먼저 제시하고, 근거와 필요한 조치를 이어 쓴다. 배경 설명은 판단에 필요한 만큼만 둔다. 별도 핵심 요약 표시가 꺼져 있어도 첫 본문에는 중요한 결론이 남아야 한다. 확인된 사실, 분석, 제안과 미확인 범위를 명확히 구분하며 확인 사항에는 판단에 영향을 주는 공백만 한 번 기록한다.

서식은 내용을 전달하는 수단이다. □ 항목의 2~3줄은 작성 목표이며 글자 수 할당량이 아니다. 중요한 사실·대상·조건을 빼거나 같은 설명을 반복해 형식을 채우지 않는다. 표·도식·강조는 설명에 도움이 될 때만 사용한다. 표의 행·셀 한도를 맞추기 위해 조사 대상이나 조건을 조용히 누락하지 않고 다른 표 또는 본문에 보존한다. 기존 스키마와 검증 한도는 유지하며, 새 초안 작성 과정에서 범위·근거·누락·중복을 점검한다. 기존 승인·동결 초안은 다시 쓰지 않는다.

기술 설명은 기본 독자의 판단에 필요한 영향 범위·업무상 영향·남은 불확실성·조치로 표현한다. 사용자가 실행 가이드를 요청하지 않았다면 함수명·설정 코드·패치 절차를 나열하지 않는다. 적용 조건의 의미는 정확히 유지하고 구체적인 구현 근거는 출처에 남긴다. 표에 있는 기관별 세부 사실을 본문에 다시 나열하지 않으며, 관련된 확인 공백은 합친다. 출처가 아카이브 페이지에 있으면 확인된 개별 공지의 실제 제목을 사용하고 일반 사이트 제목이나 추정 제목으로 대체하지 않는다.

새 reference 계획은 `note_grouping=reference-note-groups-v1`로 논점별 주석을 묶는다. □와 이어지는 하위 설명을 한 묶음으로 보고 같은 출처 설명은 묶음 끝에 한 번 둔다. 다음 동급·상위 항목, 문단 구분, 표·도식에서는 새 묶음을 시작한다. 사용하지 않는 기호 단계는 실제 활성 역할을 기준으로 판단하며 표시 번호와 혼동하지 않는다. 인용 위치의 윗첨자와 출처별 연결은 유지한다.

출처 하나를 공유하는 표는 반복 표식을 정리하고 바로 아래에 `자료: 출처 제목`을 표시한다. 표제·셀별 원래 인용 텍스트와 출처 ID·위치는 동결 계획에 남기며 ReportDraft의 사실·출처·URL·발행일을 바꾸지 않는다. 출처가 여러 개인 표는 각 인용 위치를 구분한다. 표식만 있는 셀을 비우지 않으며, 이전 정책의 동결 미리보기·저장 문서는 보존한다.

## 2026-10-25 — 새 보고서의 인쇄용 주석과 표 배치

새 reference 보고서의 문단·표 아래 주석과 별도 참고자료에는 **출처 제목만** 표시한다. 표식·윗첨자 연결과 같은 문단·표 안의 중복 제거, 다음 단위의 번호 초기화는 유지한다. 제목 자체에 포함된 날짜는 제목의 일부로 보존한다. 별도 발행일·URL은 인쇄 문구에 덧붙이지 않으며, 원래 출처 ID·제목·발행일·URL은 저장된 ReportDraft에 그대로 남긴다. `note_presentation=reference-note-titles-v1`은 새 미리보기 계획에서만 선택한다. 이미 동결한 미리보기와 저장본에는 소급 적용하지 않는다.

확인 사항도 선택된 문단 내용 기호와 들여쓰기를 사용하며 각 항목에 ‘확인 사항:’을 반복하지 않는다. 새 생성 지시는 확인 사항에도 `[S1]` 형태의 실제 출처 토큰을 쓰게 한다. 기존 초안에서 명확한 `S1~S3` 범위가 모두 등록 출처에 해당하면 새 계획에서만 해당 주석으로 연결한다. 알 수 없는 출처·단일 제품명·URL을 추정해서 바꾸지 않는다. 새 출처 작성 시 제목과 주소를 분리하고, 발행일은 확인한 정밀도의 날짜 하나만 쓰며 모르면 비워 둔다. 기존 불완전한 날짜를 자동 보정하거나 중요한 사실·날짜를 삭제하지 않는다.

새 표는 `table_layout=reference-content-columns-v1`로 전체 폭·들여쓰기·글꼴·셀 여백을 유지하면서 열별 내용에 따라 너비를 배분한다. 짧은 구분 열은 읽을 수 있는 폭을 확보하고 긴 설명 열에 남는 폭을 준다. 폭이 허용하면 식별자와 짧은 열 항목을 한 줄에 넣으며, 긴 문자열 때문에 표를 확장하거나 글자를 줄이지 않는다. 주석 정렬은 명시된 표준 값을 우선하고, 정렬값이 없는 새 주석만 왼쪽 정렬을 사용한다. 이전 정책의 표 너비와 동결된 텍스트·설정·해시는 유지한다.

## 2026-10-20 — 원문 기준으로 새 문서 표준 구성

사용자의 원문 기반 검수 요청에 따라 **새 문서 표준 revision 3은 이 절을 우선**한다. 아래 2026-10-07~18의 추가 서식은 이전 요청·revision 1/2·동결 초안의 재현 기준으로 보존한다. 새 기본값에 15pt 왼쪽 정렬, 파란 표, 별도 핵심 요약, 괄호 요약 말머리를 섞지 않는다. 기준 HWPX와 기존 `profile.json`, 원본·과거 문서, 기존 템플릿은 변경하지 않는다.

기준은 해시가 고정된 `backend/app/assets/document-standard/reference.hwpx`의 앞부분 「문서작성 표준」과 별첨 예시다. 명시된 규격이 예시 XML의 우연한 서식과 다르면 명시 규격을 우선한다. API의 `source`와 `rules`는 원문 위치, 예시 값, 적용한 규정과 차이를 제공한다. 문단 ID가 중복되는 원문이므로 위치는 XML 경로와 순번으로 기록한다.

- A4 세로, 위·좌·우 20mm, 아래·머리말·꼬리말 10mm. 본문 휴먼명조 14pt·양쪽 정렬·160%, 참고·주석 12pt·130%를 기본으로 한다.
- 제목 단계, 본문, 기호/번호 단계, 표 제목·단위·내용·출처, 표지 제목·작성일·부서, 목차 큰/작은 항목, 붙임 제목의 글꼴·크기·장평·자간·강조·정렬·줄간격·문단 간격·들여쓰기를 구분한다. 별도 예시가 없는 깊은 번호 단계와 기호는 본문 서식을 상속하며 출처 정보에 명시한다.
- 표는 가운데 정렬·110%, 회색 첫 행·검은 선·좌우 바깥선 없음, 최소 높이 7mm, 좌우 여백 1.8mm·상하 0.5mm를 기본으로 한다. 표 폭의 원문 예시 비율은 근거로 보존하되 2026-10-23 사용자 요청에 따라 새 기본값은 좌우 용지 여백 안 본문 가용 폭의 100%로 한다. 기존 등록 서식의 명시 폭은 유지한다. 제목의 파란 상하선·높이, 표지 틀, 목차 상자와 여백도 편집한다.
- 번호·기호와 주석 표식을 선택한다. 새 기본 `자동`은 같은 문단·표·도식의 서로 다른 주석이 1개면 `*`, 2개 이상이면 첫 주석부터 `주1)`, `주2)`로 표시한다. `별표 고정`(`*`, `**`)과 `번호 고정`(`주1)`, `주2)`)도 선택할 수 있다. 새 초안의 canonical 출처 ID와 사실은 유지하고, 선택한 표식과 윗첨자는 미리보기 계획을 고정하기 전에 적용한다. 숫자·날짜·시간·문장부호 규정은 새 작성 지시에 전달하며 기존 사실을 사후 치환하지 않는다. 괄호 말머리 OFF가 번호 `(1)`나 사실·조건을 지우지 않는다.
- 쪽번호는 실제 필드를 사용한다. 원문에는 전용 쪽번호 글꼴·크기가 없으므로 문자식 쪽번호는 출처 서식을 상속한다. 이를 원문에서 추출한 전용 규격으로 표시하지 않는다.

기본 프리셋은 원문 **별첨 1(표지·목차 없음), 별첨 2(표지와 목차 분리), 별첨 3(표지 안 목차)**다. 왼쪽 설정을 바꾸면 오른쪽 실제 rhwp 샘플을 다시 렌더링하며, 등록은 해당 설정과 확인한 샘플 해시를 함께 고정한다. 프리셋만 바꿀 때는 사용자가 편집한 나머지 값을 유지하고, 원문 기본값 복원은 별도 동작이다. 2026-10-24부터 편집 화면은 아래의 공통 합성 샘플을 사용한다. 이전의 원문 별첨 발췌 예시와 등록 파일은 기존 계약으로 보존한다. 원문 전체 보기의 문구는 그대로 보존하며 예시의 2015년 날짜·부서·업무 사실을 새 보고서 내용으로 복사하지 않는다.

문단 구분의 상위 단계를 끄면 더 깊은 단계를 함께 끄며, 깊은 단계를 켜면 필요한 상위 단계를 켠다. 새 초안 작성 시 괄호 요약어가 있는 상위 항목은 짧은 개요·결론을 담고, 담당자·날짜·조건·출처 등 상세 사실은 필요한 하위 항목에 보존한다. 저장된 초안의 문장을 사후 재작성하지 않는다.

표 너비는 용지 본문 폭 또는 선택한 기호·주석의 들여쓰기를 기준으로 한다. 기호 시작점 0%, 기호와 내용 사이 중간 50%, 내용 시작점 100% 중 수치로 지정하고 오른쪽 문단 여백까지의 가용 폭에 표 너비 비율을 적용한다. 주석 들여쓰기 0은 기존 주석 자동 정렬과 같이 ㅇ 항목 내용 위치를 기준으로 계산한다. `NOTE_SHORT`는 같은 단위에서 `주1), 2)`로 표시하고 다음 문단·표에서 다시 시작한다.

변경 전·후 비교는 같은 합성 자료의 실제 엔진 화면을 나란히 보여 준다. 2026-10-25부터 기본으로 켜며, 설정 역할 전체에 배경색을 칠하는 대신 측정한 글자·서식·줄 배치 차이에만 얇은 밑줄을 표시한다. 앞 문단 편집 때문에 그대로 아래로 이동한 문단은 제외한다. 괄호 요약어는 추가·삭제된 문구만 표시하며 비교 중에는 마우스 위치 안내의 넓은 배경 강조를 겹치지 않는다. 밑줄은 왼쪽 변경 설정과 같은 색이며 ‘변경 위치’ 쪽 버튼으로 이동한다. 글자가 없는 테두리·채움 등은 이 글자 비교로 검출하지 않으며 화면 자체로 비교한다. 원본 픽셀 전체를 비교하는 기능은 아니다.

### 2026-10-25 — 주석 위치와 내용 기준 전후 비교

## 구현 범위

이번 금융권 보고서는 `scripts/build-standard-report.py`와 `scripts/render-standard-report.mjs`의 독립적인 산출물 작성 절차로 만들었다. 승인된 내용은 새 빈 스캐폴드에 rhwp exact commands로 적용했고, 그 출력 문단을 이용해 표지·표·목차를 배치했다. 기존 문서나 사용자 편집 버퍼를 대상으로 실행하지 않았다.

`/api/report-tasks`에서 새 초안을 승인하면 이제 이 기준서에서 추출한 서식을 자동 적용한다. 별도 표지 없는 보고서 제목의 파란 상하선, 휴먼명조 14pt 본문, HY헤드라인M 제목, 160% 줄간격, 항목 들여쓰기, A4 여백과 쪽번호를 적용한다. 긴 문단은 텍스트를 보존하면서 나누고 표준 글자 크기에 맞춰 페이지를 미리 배정한다. 실제 텍스트 적용은 기존 rhwp exact commands와 영수증 검증을 그대로 거친다. 자동 표·이미지 작성이나 자동 목차 생성까지 구현한 것은 아니다.

승인에 기준 ID·원본 해시·설정 해시를 고정하고 저장된 스캐폴드의 서식과 실제 출력을 대조한다. 이전에 승인한 작업은 현재 기준으로 몰래 재작성하지 않는다. 기준 파일이 없거나 원본 해시가 다르면 다른 서식으로 대체하지 않고 새 승인을 중단한다. 생성 화면의 ‘기준서 원본 보기’ 링크와 `/api/document-standard`에서 기준을 확인할 수 있다.
