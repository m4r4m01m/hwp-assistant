# 개발 순서와 2인 트랙

최신 사용자 방향: LLM을 먼저 배치해 AI 기능을 확인한다. A가 AI 고도화, B가 시스템을 병렬 진행하는 안으로 단순화한다. 실명 담당·마감일·가용 시간은 미확정이다.

## 1. 시간순 개요

아래 단계는 주차나 기간이 아니라 진행 순서다. 과거 WBS의 A/B 역할과 다르므로 현재 작업 배치에는 이 문서를 우선한다.

```text
시간 흐름      시작·계약             기능별 병렬 개발              연결·검증             데모·이식
────────────────────────────────────────────────────────────────────────────────────────────────
A: AI          실제 LLM 호출     →   초안·검토·출력 검증       →   승인 적용 연결    →   품질·시간 측정
B: 시스템      편집기·HWPX 시험  →   드라이브·저장·버전       →   템플릿·충돌 처리 →   왕복·격리 시험
공동           요청/응답 계약        합성 문서·회귀 사례 공유       통합 관문 통과        근거 있는 발표
```

드라이브 완성을 기다린 뒤 AI 개발을 시작하지 않는다. 동시에 HWPX 위험을 마지막까지 미루지 않도록 B 트랙에서 편집기와 왕복 시험을 초기에 진행한다.

## 2. 단계별 결과물

| 순서 | A: AI 중심 | B: 시스템 중심 | 함께 확인할 결과 |
|---|---|---|---|
| 1. 최초 검증 | 개발 모델 실제 호출, 교체 경계, 초안·검토 최소 예제 | 편집기 자체 실행, 원본 보관, 무편집/단순 편집 왕복 | AI 가능성·HWPX 위험을 실제 결과로 확인 |
| 2. 기능 뼈대 | 구조화 출력, 누락 정보 표시, 규칙 검사, 오류 처리 | 문서/폴더/버전 모델, 업로드/다운로드, 서버 저장 | 문서 ID·버전·선택 범위 계약 일치 |
| 3. 사용자 기능 | 제안 비교·선택 승인·오래된 제안 차단 | 파일 관리·복원·세션/충돌, 템플릿 저장·삽입 | AI 변경과 일반 편집이 동일한 저장 경로 사용 |
| 4. 통합 품질 | 응답 품질·속도·동시 요청·장애 회귀 | 한글 왕복·반복 편집·저장 실패·템플릿 회귀 | 내용 누락·잘못된 덮어쓰기 방지 근거 |
| 5. 발표·이식 | 실제 사용 시나리오·효과 측정 | 컨테이너·설정·반입·격리 실행 | 외부 통신 없는 핵심 흐름과 남은 한계 |

B 트랙이 과도하게 커지면 A가 AI 핵심 검증 후 통합 UI·템플릿 일부를 지원한다. 역할 분리는 고정된 프런트/백엔드 분업이 아니라 주도 책임의 구분이다.

## 3. 통합 관문

**G1 — 실제 검증:** 모델 실제 호출 근거와 편집기 HWPX 시험 결과를 확보한다. Mock 화면만으로 통과하지 않는다.

**G2 — 안전한 통합:** 승인된 AI 변경만 적용되고, 저장 실패·기준 버전 불일치 시 기존 파일과 최신 버전을 보호한다.

**G3 — 왕복 보존:** 한글→웹→한글→웹의 편집 흐름, 템플릿 삽입, 버전 복원 회귀를 기록한다. 지원 범위와 실패 문서를 함께 남긴다.

**G4 — 이식 가능성:** 사전 반입한 구성만으로 인터넷 차단 환경에서 실제 AI를 포함한 핵심 기능을 실행한다. 실제 회사 운영 배포 완료와는 구분한다.

## 4. 첫 작업 지시

A는 합성 업무보고 입력으로 초안과 선택 문단 검토를 각각 실제 모델에 요청하고 모델 정보·지연·출력 검증 결과를 남긴다. B는 합성 HWPX를 원본 보관·무편집 재저장·문단 또는 표 수정 후 실제 한글에서 비교한다.

공동으로 문서 ID·기준 버전·원문 해시·제안 상태를 먼저 합의한다. 회사의 전체 장비·망 사양을 알아야만 시작할 수 있는 구조로 만들지 않는다.

## 5. 진행 관리

작업별 담당·범위·선행조건·인수기준을 이슈에 기록하는 안을 사용한다. 이 문서와 보관된 WBS는 이슈를 자동 생성하거나 상태를 동기화하지 않는다. 이번 작업에서는 GitHub 이슈를 만들지 않았으며 현재 이슈 존재 여부도 이번 문서 반영 작업에서는 확인하지 않았다.
