# 실제 사용자 승인 시험 실행

**2026-10-06 안내:** 아래 “현재 제공한 창”과 “실행 중”은 2026-09-27 당시의 기록이다. 그 시험의 실제 사용자 승인·저장 완료 후속 근거는 [완료 기록](evidence/codex-human-completed-2026-09-27.json)에 있다. 과거 PID·포트·창이 지금도 실행 중이라고 가정하지 않는다. 하네스에는 `--provider codex|llm`이 추가됐으며, 로컬 모델 재개는 [새 안내](local-model-rewrite.md#실제-모델과-사람-승인-시험-재개)를 따른다. 이번 10/06 개발 시험에서는 실제 모델이나 사람 승인 시험을 새로 실행하지 않았다.

기존 API/Vite가 `http://127.0.0.1:15174`에서 동작하는 Windows 환경용이다. 설치된 Playwright 1.56.1과 Chrome을 사용한다. 이전 `.cache/codex-flow/verify.mjs`와 해당 실행은 보존한다.

## 현재 제공한 창

2026-09-27 새 시험이 **실행 중**이다. Chrome 제목은 `HWP Assistant · 사용자 승인 시험 · waiting_for_user_approval`이며, 실제 Windows 대화형 세션 1에서 visible=true / minimized=false를 확인했다. 함께 실행한 PowerShell도 유지한다. 아래 명령을 다시 실행할 필요가 없다.

- 작업: `ca00261c-b9f0-4d91-8263-4b3641b3ad65`
- 문서: `95270b84-65ab-459c-a806-33fbc758e892`
- 후보 1: `78c8ef0d-c714-5e4c-9200-47519caa7573`
- 후보 2: `b1fb6743-d42e-5476-a2ad-a70200160ad0`

오른쪽 비교 화면에서 AS-IS와 후보를 읽고 원하는 **후보 N 승인·적용·저장** 버튼을 직접 클릭한다. 하네스는 후보를 선택하지 않는다. Enter, Inspector Resume, 별도 선택 파일, 채팅의 추천은 승인으로 처리하지 않는다. 비교 중에는 문단 편집·다른 저장·탭 새로고침을 하지 않는다. 변경했다면 충돌로 중단하고 현재 창과 내용을 보존한다.

실행에 사용한 정확한 명령:

```powershell
Set-Location 'C:\Users\alsdu\Documents\ChatGPT\hwp-assistant'
node .\scripts\verify-codex-human.mjs --url http://127.0.0.1:15174 --out .cache/codex-human-2026-09-27-run2
```

같은 출력 경로는 `proof.json`의 배타적 생성으로 재실행을 거부한다. 다른 경로로 실행하면 별도 합성 문서와 실제 AI 요청을 만들기 때문에, 이번 시험을 재호출하기 위한 용도로 사용하지 않는다. 이번에 허용된 실제 Codex 재실행 1회는 이미 사용했다. `--help`는 실행 방법만 출력하며 브라우저/모델을 시작하지 않는다.

## 승인 전후의 연결

1. 하네스는 headless=false로 실제 창을 열고 대화형 Windows 세션의 가시성을 확인한다. 확인에 실패하면 AI 요청 전에 중단하며, 사용자가 자신의 PowerShell에서 실행해야 한다고 표시한다.
2. 제품 UI로 합성 문서 생성·최초 저장·재열기를 수행한다. 대상 문단과 대상 외 문단에 각각 미저장 문장을 입력한다.
3. 제품의 실제 Codex 버튼으로 한 번만 요청한다. 두 번째 POST는 시험 하네스에서 차단한다. 모델/API 키 대체 경로는 없다.
4. 모델 입력·비교 화면·현재 에디터 스냅샷의 일치, 확정 버전 1개 유지를 검사한다. 같은 창에서 사용자 버튼 클릭을 기다린다.
5. 이 창의 실제 DOM 클릭, 해당 후보에 대한 승인 HTTP 응답, 서버 적용 이력의 후보 ID를 연결한다. 서버의 기준/임대 검사와 rhwp 원문·편집 상태 검사는 제품 경로 그대로 실행된다.
6. 적용 영수증·저장 성공·새 버전 1개·다운로드 해시를 확인한다. 미대상 문단 구조/텍스트와 리소스, 대상 외 미저장 문장, 이전 원본을 비교한다. 성공한 다음에만 같은 브라우저에서 목록으로 이동해 저장본을 다시 연다.

브라우저와 터미널은 승인 대기, 실패, 성공 후에도 자동으로 닫지 않는다. 터미널을 강제로 종료하지 말고 결과를 확인한 다음 창을 직접 닫는다. 오류가 나면 입력/후보를 남기며 자동 재호출·강제 적용·XML 재작성은 하지 않는다. 실제 충돌 후 자동 복원이나 범용 브라우저 복구 기능은 제공하지 않는다.

현재 증거는 `.cache/codex-human-2026-09-27-run2/proof.json`에 계속 기록된다. 성공하면 같은 폴더에 다운로드한 `saved-synthetic.hwpx`와 `reopened.png`도 생긴다. 파일의 존재 여부와 `stages`를 확인해야 하며, 현재 승인 이후 단계는 아직 미실행이다. 정적 기록은 `docs/evidence/codex-human-2026-09-27.json`에 있다.

## 이번 수정과 시험의 한계

첫 준비 실행은 로그인 화면을 기다리지 않아 401로 중단됐다. 이때 모델 호출은 0회였고 증거는 `.cache/codex-human-2026-09-27/`에 남겼다. 로그인 화면과 응답을 기다리도록 하네스만 수정했다.

다음 실행의 실제 후보 생성 후에는 하네스의 JSON 문자열 비교가 대상 객체의 키 순서를 충돌로 잘못 판단했다. 구조 비교로 고쳤으며, 키 순서만 다른 동일 대상은 허용하고 리비전/문서 해시/원문 해시/문단/기준 변경은 거부하는 회귀 시험을 추가했다.

이미 열린 새 창을 잃거나 AI를 재호출하지 않기 위해 이번 하네스 프로세스만 일회 로컬 Node 디버깅으로 기존 Playwright 객체에 다시 연결했다. 같은 페이지에서 실제 버퍼와 기준이 맞는지 읽은 뒤 수정된 후속 검증 함수를 연결했다. 이 과정은 후보 승인이나 문서 저장이 아니며, 문서 ID·리비전·해시·영수증·DB를 수정하지 않았다. 임시 디버거 연결은 종료했고 9229 포트의 listener가 없음을 확인했다. 정상 명령은 수정된 후속 함수를 직접 호출하므로 이 디버깅 절차가 필요하지 않다.

```powershell
node --check scripts/verify-codex-human.mjs
node --check scripts/verify-codex-human-continuation.mjs
node --check scripts/verify-codex-human-tools.mjs
node --test scripts/verify-codex-human.test.mjs
node scripts/verify-codex-human.mjs --help
```

위 검사와 회귀 시험 1개는 통과했다. 해당 회귀 시험은 고정 객체의 하네스 검사이며 실제 사용자 승인 시험이 아니다. 제품 코드는 수정하지 않았고 기존 충돌/중복 방지 시험은 보존했다. 사용자 승인·적용·저장·웹 재열기는 실제 버튼 클릭 이후 결과로만 판정한다. 웹 재열기는 한컴 왕복 검증이 아니다.
