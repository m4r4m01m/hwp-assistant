# 편집 가능한 한글 초안과 지정 보고서 서식 보완

2026-10-07. 대상은 사용자가 웹에서 생성·저장한 **금융권 해킹 동향 및 90일 대응계획 경영진 보고.hwpx**다. 이전 상세 보고서나 가이드 적용 결과를 이 파일의 검증으로 대신하지 않았다.

## 발견 사항과 수정

지정 원본을 실제 rhwp로 열면 8쪽이며, 긴 제목의 마지막 글자 `고`가 혼자 다음 줄에 남고 각 절의 강제 새 쪽 시작 때문에 큰 빈 공간이 생겼다. 적용 직후 출력에 남은 줄 배치 정보와 엔진의 불완전한 어절 나눔 때문에 XML의 내어쓰기 설정만으로 기대한 화면을 얻지 못했다.

`report_layout.py`는 영수증·내용·기준 서식 검증을 통과한 새 초안만 배치한다. 제목은 어절 경계에서 균형 있게 나누고, 지정 글자 크기·문단 여백을 유지하면서 강제 절별 페이지 나눔을 제거했다. 현재 엔진의 호환성 보완으로 공백과 모든 문자를 보존하는 문단 안 줄바꿈을 넣고 줄 배치를 다시 계산한다. 문구를 줄이거나 사실·출처를 수정하지 않았다. 파란 위·아래 제목선과 □·○·- 계층 및 내어쓰기를 유지했다.

개선본은 6쪽이다. 실제 rhwp 재열기, HWPX→PDF 출력, Poppler로 PDF 6쪽 전부를 렌더링하여 확인했다. 편집기에서 저장한 HWPX를 별도로 다시 열어도 6쪽이며 내용 손실 보고는 0이다. 엔진의 `LinesegArrayEmpty` 재배치 경고 32건은 남아 있다. 이를 경고 0 또는 한컴 검수 완료로 보고하지 않는다.

## 새 제품 흐름

1. 사용자가 프롬프트로 초안을 요청한다. 기본 AI 경로는 기존 Codex다.
2. 준비된 초안은 별도 임시 rhwp 편집기에서 기존 문서·선택·원문 fence를 가진 exact commands로 적용한다. 준비 중에는 편집할 수 없다.
3. 서버가 영수증, 명령 순서, 문단 내용, 고정 서식을 검사한 뒤 배치한다. 화면에 실제 HWPX 편집기를 표시하고 직접 편집을 허용한다.
4. `초안 확정·서버 저장`은 화면에서 직접 편집한 내용을 포함해 새 문서·첫 버전을 발행한다. 파일 영속화와 DB commit 이후 저장 완료를 반환한다. 미리보기 준비만으로 문서·버전·blob을 만들지 않는다.
5. `보고서 편집하기`로 기존 일반 편집·자동 저장 흐름에 연결된다. 기존에 이미 저장한 보고서에도 편집 버튼을 제공한다.

미리보기 계획·서식·출력은 작업의 기존 execution JSON에 고정하고, 응답 유실 시 이를 다시 읽는다. 준비 응답을 잃어도 같은 준비 ID/seed를 유지한다. 렌더 응답을 잃으면 저장된 배치 결과를 복구한다. 저장 중에는 편집을 잠그며 출력 바이트·저장 ID를 유지해 같은 요청으로 재확인한다. 재시도에도 현재 소유 권한을 검사한다. 기존 승인·저장 경로는 이전 미완료 작업의 호환성을 위해 보존했다.

초안 직접 편집 내용은 확정 전 자동 저장되지 않는다. 닫기·새로고침에는 경고가 있고, 복구용 HWPX 다운로드를 제공한다. 브라우저가 강제로 종료되면 미확정 직접 편집 내용의 복구는 보장하지 않는다. 문서 목록의 기존 편집 버퍼에는 접근하지 않는다.
