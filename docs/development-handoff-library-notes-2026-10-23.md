# 문서함 드롭·자동 주석·표준 설정 인계 — 2026-10-23

기준 브랜치는 `codex/local-ui-qa-2026-10-22`, 작업 시작 HEAD는 `5977f337b17a6f6e35aa5cf20b4496194cf3ce16`이다. 변경을 구현·검증하고 로컬 QA 서비스에 반영했다. 상세 증거와 보존 해시는 [library-notes-2026-10-23.json](evidence/library-notes-2026-10-23.json)에 있다. 최종 실행·통합 검증은 마지막 절을 참고한다.

## 구현

- 문서함 본문에 HWPX 한 개를 놓으면 기존 업로드 흐름으로 새 문서를 만든다. 최대 30 MiB이며 복수 파일은 전부 거절한다. 같은 이름의 파일도 기존 문서를 덮어쓰지 않는다. 응답이 유실되면 파일 바이트·이름·문서 UUID·저장 키를 고정해 결과를 재확인하며, 처리 중에는 다른 업로드를 막는다. 드롭 영역 밖의 파일 놓기로 브라우저가 이동하는 것도 방지한다.
- 새 revision-3 표준의 주석 기본값은 `AUTO`다. 같은 논리 문단·표·도식에서 서로 다른 출처가 하나면 `*`, 둘 이상이면 첫 것부터 `주1)`, `주2)`를 쓴다. 반복 인용은 하나로 세고 다음 단위에서 초기화한다. 예를 들어 `[S8][S4][S8]`은 `주1), 주2), 주1)`이며 다음 단위의 `[S4]`는 `*`다. 본문 표식과 바로 뒤 설명이 같은 번호를 쓰며 원래 출처 ID와 사실은 유지한다.
- 기존 `STARS`와 `NOTE`의 뜻, 등록 설정·해시, 동결 요청·미리보기·저장 재시도는 유지한다. 기존 지역 주석 정책 `reference-local-notes-v1`도 유지한다. 새 AUTO 기준서 파생 미리보기만 정확히 연결된 세 주석 설명을 `주1) → 주2) → 주3)` 순서로 배치하며 원문 내용과 연결을 보존한다. 원본 보기와 고정 표식 미리보기는 바꾸지 않는다.
- 문서 표준 편집은 `자주 쓰는 설정`을 먼저 보여주고 면 표시·주석을 상단에 연다. `상세 설정`에는 모든 기존 제어가 남아 있으며 검색은 두 모드와 관계없이 전체 설정을 찾는다.

주요 제품 파일은 `frontend/src/main.tsx`, `workspace-shell.css`, `standard-designer.tsx`, `standard-designer.css`와 `backend/app/report_contract.py`, `report_notes.py`, `reference_standard.py`다. 작성 기준은 `docs/document-writing-standard.md`의 해당 절만 보완했다.

- 브라우저 고유 시나리오 **6개 통과**: 문서함 브라우저/API 2개, 실제 rhwp 표준·보고서 4개. 문서함 시험은 rhwp를 사용하지 않았다. 표준 시험은 설정 반영, 잘못된 설정/오래된 미리보기 보호, 등록 응답 유실 재확인을 포함한다. 보고서는 합성 초안으로 지역 표식·원문 출처 보존, 서버 저장·웹 재열기 바이트 일치를 확인했다.
- TypeScript·프로덕션 빌드·실제 제공 자산 바이트 확인이 통과했다. 기존 rhwp 0.8.6 진단 빌드를 재사용했고 엔진 소스는 변경하지 않았다. 격리 시험 리스너 잔여 0개, 실제 모델 호출 0회, 사용자 저장소 사용 없음이다.

## 색상 조사와 HWP 다운로드 후속

색상 후속 증거는 [hancom-color-compatibility-2026-10-23.json](evidence/hancom-color-compatibility-2026-10-23.json)에 정리했다. 이 컴퓨터의 Hancom 2018에서 사용자 PHP 보고서의 XML `#437FC1`이 주황색으로 보였다. 부모 작업이 한컴에서 직접 순수 빨강으로 작성·저장한 합성 `NATIVE RED 2026` 문서는 실제 활성 글자 속성에 `#0000FF`를 기록했고 rhwp는 이를 파랑으로 읽었다. 해당 통제 파일 SHA-256은 `011ba1c5e2ca878850e60c60abf427d596de74794f1abca5d8b0c8bdf2eaa955`다. 이 설치 경로의 빨강·파랑 해석 차이를 뒷받침하지만 모든 한컴 버전이나 공식 HWPX 규격의 오류라고 일반화하지 않는다. 정본 RGB나 원본 파일을 일괄 치환하지 않았다.

격리한 실제 WASM에서 PHP 보고서를 HWP로 내보내고 재열어 **7쪽·108문단·표 4개·텍스트 run 221개의 순서와 활성 글자·표 색상**이 유지됨을 확인했다. 사용되지 않던 헤더의 `#FFFFFFFF` 채움 두 개는 없어졌으므로 전체 XML이나 모든 색상 항목이 같다는 주장은 하지 않는다. 별도의 RGB 합성 자료도 **1쪽·14문단·표 1개·도형 3개**, 글자·표 채움·테두리·도형 채움·선·크기가 유지됐다. 두 변환의 손실 보고는 0건이나, 이것이 모든 서식의 완전 보존을 증명하지는 않는다.

`frontend/src/hancom-download.ts`의 새 경로는 선택한 서버 저장본의 크기·해시를 확인하고, 편집기와 분리된 엔진에서 같은 export artifact의 손실 보고와 HWP 바이트를 받는다. 손실 0건, CFB 서명, 재열기 후 본문·쪽수 일치를 검사한 뒤 다운로드한다. 입력·출력 각각 30 MiB, 500쪽 한도이며 원본·과거 버전과 현재 미저장 편집은 바꾸지 않는다. 원본 HWPX 링크와 별도 `한컴 2018용 HWP` 선택을 제공하는 공통 다운로드 UI도 구현됐다. TypeScript·diff 검사와 전용 브라우저 성공·차단 시험 2개가 통과했다. 최종 실행 결과는 아래 절에 정리했다.
