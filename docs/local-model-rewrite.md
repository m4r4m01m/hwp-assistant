# 로컬·사내 모델의 선택 문단 후보 생성

2026-10-06 구현 안내. 기존 `RewriteTask → RewriteCandidate → Application → Version`과 rhwp 승인 적용 경로를 재사용한다. 새 편집기·저장 체계·AI SDK·DB 마이그레이션은 추가하지 않았다. 실행 결과는 [날짜별 검증 기록](verification-2026-10-06.md)에 별도로 남긴다.

## 실행 경로 선택

서버 환경변수 `HWP_REWRITE_PROVIDER`로 **선택 문단 후보 2개 생성** 경로를 선택한다. 이 설정은 기존 한 개짜리 검토와 대화 질문의 `LLM_*` 설정을 대체하지 않는다.

| 값 | 동작 | 실행 조건 |
|---|---|---|
| 미설정 또는 `codex` | 기존 Codex CLI와 작업 전용 MCP | `HWP_CODEX_USER`에 연결된 앱 사용자, 설치된 CLI·기존 ChatGPT 로그인·MCP 의존성 |
| `llm` | 기존 `LlmProvider`의 OpenAI 호환 HTTP 호출 | 서버의 `LLM_*` 설정, 문서 editor/owner 권한과 본인 편집 임대 |
| 그 외 | 설정 오류, 생성하지 않음 | 다른 제공자로 전환하지 않음 |

로컬 경로는 Codex 로그인·프로세스·MCP가 없어도 사용할 수 있다. `HWP_CODEX_USER`가 다른 사용자여도 로컬 경로의 문서 편집 권한은 별도로 판단한다. reader·외부 사용자·권한 회수 사용자의 쓰기 권한을 넓히지 않는다. 브라우저는 모델 주소·키·모델 ID를 지정할 수 없다.

네이티브 API를 시작하는 PowerShell에서 다음을 설정한다. `.env`는 네이티브 서버가 자동으로 읽지 않는다.

```powershell
$env:HWP_REWRITE_PROVIDER='llm'
$env:LLM_PROVIDER='openai-compatible'
$env:LLM_BASE_URL='http://127.0.0.1:1234/v1'
$env:LLM_MODEL='<해당 서버 /models에서 확인한 실제 ID>'
$env:LLM_TIMEOUT_SECONDS='30'
# 인증이 필요한 모델 서버에만 실제 키를 실행 환경으로 전달한다.
# $env:LLM_API_KEY='...'
```

`LLM_TIMEOUT_SECONDS`는 0 초과 240 이하의 유한한 수다. 주소는 http/https와 호스트가 있어야 하며 URL 내부 사용자명·암호·쿼리·fragment는 허용하지 않는다. 프록시 환경변수와 HTTP 리디렉션을 따르지 않는다. 유료 OpenAI 서버 도메인을 거부하며 다른 AI로 자동 대체하지 않는다. 관리자가 승인한 로컬·사내 서버 주소만 설정한다.

`GET /api/rewrite-provider`의 `configured`는 **설정 형식 확인**이다. 실제 연결 성공이나 모델 사용 가능성을 뜻하지 않는다. **AI 연결·모델 확인**은 `/models`를 조회한다. 목록에 있는 모델 ID를 그대로 설정하고, 이름이 비슷한 다른 모델로 추측해서 바꾸지 않는다. “Qwen 3.8”의 실제 ID·크기·API 규격은 아직 확인되지 않았다.

## 사용과 입력 범위

1. 문서를 최초 저장하고, 편집할 **본문 단일 서식 문단**에 커서를 놓는다.
2. **문서 AI 대화 → 대화 이름 입력 → AI와 대화 시작** 또는 기존 대화를 선택한다.
3. **문단 수정 후보 · 직접 요청**에서 표시된 현재 생성 경로·모델을 확인하고 **로컬·사내 모델로 후보 2개 요청**을 누른다.
4. AS-IS와 두 후보·이유를 비교한다. 사용자가 **후보 N 승인·적용·저장**을 눌러야 버퍼 적용과 서버 저장을 진행한다.
5. `저장 완료`와 적용 이력의 저장 버전을 확인한다. 다운로드/export만으로 서버 저장 성공을 판정하지 않는다.

요청 순간의 **미저장 문단**과 개선 지시만 모델에 전달한다. 선택 스냅샷·기준 버전·원문/서식/인접 문맥 해시는 작업에 고정한다. 현재 구현은 대화의 작성 목적·확정 사실·작성 기준·대화 내역을 이 두 후보 요청에 넣지 않으며 화면에도 그 사실을 표시한다. 기존 **설정된 AI에 질문**의 컨텍스트 사용과 구분한다.

고정된 rhwp 0.8.6 exact command의 제한에 맞춰 대상과 후보는 최대 **4,000 Unicode 코드포인트**의 단일 본문 문단이다. 줄바꿈·탭·제어 문자가 있는 대체 문장은 거부한다. 표 셀·필드·컨트롤·혼합 글자 서식 문단은 이 AI 명령의 대상이 아니다. 문서 첫 문단에 구역 설정이 포함되면 다음 본문 문단을 사용한다.

길이 한도 안이어도 **적용으로 문서 페이지 수가 바뀌면** 고정 엔진이 거부한다. 한도를 만족하는 모든 문장을 적용할 수 있다는 뜻은 아니다. 원문을 보존한 상태에서 더 짧은 후보를 다시 검토하거나 수동 편집으로 처리한다. 엔진의 페이지 수·비대상 문서 보존 검사를 해제하지 않는다.

모델에는 사실·이름·날짜·금액·수치·부정 표현을 보존하도록 지시한다. 이것은 사실성 판정이나 회사 규정 검증이 아니다. 사용자가 후보를 읽고 확인해야 한다.

## 응답 계약과 보관

모델은 다음 텍스트와 이유만 반환한다. 작업 ID·문서 ID·권한·승인 상태를 모델이 지정하지 않는다.

```json
{
  "candidates": [
    {"replacement": "첫 번째 문단", "reason": "첫 번째 수정 이유"},
    {"replacement": "서로 다른 두 번째 문단", "reason": "두 번째 수정 이유"}
  ]
}
```

후보는 정확히 2개, 이유는 각각 1~2,000자다. 공백·보이지 않는 문자만 있는 값, 추가 필드, JSON 중복 키, 잘린 응답, 코드 블록, 잘못된 JSON을 거부한다. 공백·NFC 정규화·보이지 않는 형식 문자를 제외했을 때 동일한 후보도 거부한다. 후보 텍스트는 검사 후 임의로 다듬거나 잘라서 보관하지 않는다. `finish_reason=stop`인 텍스트 응답만 받으며 도구 호출·거부·토큰 제한 종료는 게시하지 않는다. 서버의 JSON schema 지원을 가정하지 않고 일반 JSON 프롬프트와 서버 검증을 사용한다.

네트워크 호출 중에는 DB 쓰기 트랜잭션이나 문서 행 잠금을 유지하지 않는다. 호출 전후 문서 권한·본인 임대·기준 버전·작업 상태를 검사하고, 후보 2개와 `ready`를 한 트랜잭션으로 확정한다. 후보 생성은 HWPX·문서 버전·Application을 만들지 않는다. 로컬 작업에는 MCP 실행 토큰이 없으며 일반 사용자가 후보 등록 API로 결과를 주입할 수 없다.

실행 근거에는 제공자·설정 모델 ID·성공 여부·원문 및 정규화된 입력 SHA-256을 보관한다. 입력 해시는 원문과 개선 지시 JSON의 키를 정렬해서 계산한다. 과거 제공자 정보가 없는 작업은 기존 Codex 작업으로 표시하고, 모델 ID를 모르면 임의로 채우지 않는다. 현재 설정을 바꿔도 과거 작업의 제공자는 바뀌지 않는다. 인증정보와 내부 임대/멱등 지문은 공개 실행 근거에서 제외한다.

## 실패·중단·재시도

| 상황 | 보존 및 재개 동작 |
|---|---|
| 생성 요청 응답 유실 | 열린 탭에서 동일 ID·스냅샷·개선 지시를 보관한다. 같은 요청 버튼으로 서버 결과를 확인한다. 새 ID로 자동 생성하지 않는다. |
| 동일 ID 재요청 | 기존 작업을 반환한다. 같은 ID의 원문·기준·지시 등이 다르면 409. 완료·실패·중단 작업도 자동 재실행하지 않는다. |
| 연결·형식·timeout 오류 | 작업에 실패를 남기고 후보나 문서를 덮어쓰지 않는다. 새 요청은 사용자가 시작한다. |
| 권한·임대·기준 변경 | 늦은 결과를 새 정상 후보로 게시하지 않는다. 기존 원문과 이미 보관된 후보는 유지한다. |
| 결과 수신 중단 | 요청자 또는 문서 owner만 중단한다. 이미 시작된 HTTP/CLI 실행은 끝날 수 있으나 이후 결과 게시·적용은 막는다. |
| 서버 중단·재시작 | 모델 작업을 자동 재개하지 않는다. 아직 running인 작업은 생성 후 600초가 지나면 읽기 화면에서 expired로 표시한다. 원본 행·후보는 삭제하지 않는다. |
| 승인 후 저장 응답 유실 | 같은 후보로 재시도하면 동일 출력·영수증·저장 키를 사용한다. 저장 commit이 이미 끝났으면 추가 버전을 만들지 않는다. |
| 비교 중 문서 편집 | 편집 버퍼는 계속 유지한다. 오래된 후보 적용은 문서·선택·원문·서식·인접 문맥 fence에서 거부한다. 최신 상태로 다시 요청한다. |

비교 중에는 20초 자동 저장을 보류한다. **비교 종료 · 자동 저장 재개**로 해제하거나 수동 저장할 수 있다. 수동 저장으로 기준 버전이 바뀌면 이전 후보가 오래된 것으로 표시된다. 후보 승인 저장 성공 후 자동 저장을 재개한다. 브라우저 강제 종료 후 메모리에 있던 재시도 큐를 복원하는 기능은 없다. 서버 저장이 확인되지 않으면 **복구용 다운로드**로 버퍼를 별도 보관한다.

## 분리된 자동 검증

이 Windows 실행기는 새 출력 폴더·DB·파일 저장소·비충돌 포트·복사한 검증 엔진을 사용한다. 일반/인증/로컬 API와 웹, **명시적인 모의 HTTP 모델**을 기동하고 종료 시 자신이 만든 프로세스만 정리한다. 기존 출력 폴더 재사용을 거부한다. 실모델·Codex CLI를 호출하지 않는다.

```powershell
# 저장소 루트. EnginePublic은 이미 검증된 자체 호스팅 엔진의 public 폴더다.
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-isolated.ps1 `
  -EnginePublic .cache/engine-release-2026-09-27/public

# 별도 진단 앱 번들에서도 로컬 후보 시나리오를 실행한다.
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-isolated.ps1 `
  -EnginePublic .cache/engine-release-2026-09-27/public -BuiltApp

# 선택 실행: 실제 시계로 최소 180초 동안 자동 저장 보류·임대 갱신 확인.
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-isolated.ps1 `
  -EnginePublic .cache/engine-release-2026-09-27/public `
  -TestPattern 'long-lived review' -SoakSeconds 180
```

`-OutDir`로 새로운 결과 경로를 지정할 수 있다. `run.json`, 서비스 로그, Playwright 산출물을 보존한다. 장시간 시험은 기본 실행에서 skip하고, `-SoakSeconds`를 명시한 경우만 실행한다. 진단 번들을 사용한 통과는 최적화 배포 빌드·nginx·Compose 통과가 아니다. 엔진 검사와 기본 빌드 가드는 유지한다.

서버 프로세스 중단/재시작의 별도 합성 시험은 `scripts/verify-rewrite-restart.py --help`를 따른다. 이 시험도 명시적인 모의 모델이며 실시간 600초 만료를 선택할 수 있다.

## 실제 모델과 사람 승인 시험 재개

2026-10-06 시작 시 모델 환경변수가 없었고 `http://127.0.0.1:1234/v1/models`는 연결 거부였다. 대형 모델 다운로드·전역 설정 변경·다른 서버 추측은 하지 않았다. 실제 모델의 생성과 실제 사람 승인은 미실행이다.

재개에는 준비된 로컬·사내 서버 주소, `/models`의 정확한 ID, 필요한 경우 인증 설정이 필요하다. 기존 자료와 분리한 DB/파일 저장소와 검증 엔진을 사용하는 API·웹을 먼저 준비한다. 원격 사내 주소는 이 API 프로세스에서 접근 가능해야 한다. 네이티브 API의 localhost는 이 PC이고 컨테이너나 다른 호스트의 localhost와 다르다.

```powershell
node scripts/verify-codex-human.mjs --provider llm --user local `
  --url http://127.0.0.1:5173 --out .cache/local-human-새로운실행이름
```

인증된 분리 서버에서는 `--user`와 `HWP_TEST_APP_TOKEN`을 해당 시험 사용자에 맞춘다. 하네스는 설정과 실제 모델 ID를 확인하고, 합성 문서에 대해 생성 요청을 한 번만 시작한다. 모의 모델 `hwp-synthetic-fixture`는 이 사람 시험에서 거부한다. 실제 창의 제품 후보 버튼을 사람이 눌러야 승인 이후로 진행한다. Enter, Resume, 파일 생성, 개발 지시는 후보 승인이 아니다. 실패를 숨기고 좋은 답이 나올 때까지 반복하지 않는다.

이름·날짜·금액·부정 표현의 문자 보존 확인을 보조 근거로 남기지만, 의미 보존은 사람이 별도로 판단해야 한다. 실제 사용자 선택이 없으면 승인·적용·저장·재열기를 미실행으로 남긴다. 로컬 모델 성공·사내 모델 성공·한컴 왕복·인터넷 차단 시험은 각각 별도 검증 항목이다.
