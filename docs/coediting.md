# 문서 공동편집과 로그인 세션

## 2026-10-30 진입 흐름 변경

계정 기능을 사용하는 공유 문서는 문서 이름 또는 이력의 **편집**을 누르면 내 작업본으로 열린다. 별도 공동편집 버튼은 없다. `/documents/{id}/edit-target`이 원본 잠금 아래 계정별 자동 작업본을 생성·재사용하며, `work_copy_entries`에 열기 요청 영수증을 저장한다. 동일 요청 재확인은 같은 작업본을 가리키고 다른 계정/문서에서 재사용하면 거부한다. 열람자는 작업본을 자동 생성하지 않고, 공유하지 않은 개인 문서와 계정 미사용 환경은 기존 편집기를 사용한다.

사용자별 작업본은 서로 다른 가지에 저장한다. 같은 작업본에 명시적으로 초대된 참여자만 그 작업본에서 아래 실시간 동기화를 함께 사용한다. **문서 이력·검토 → 통합 요청** 후 해당 수정에 참여하지 않은 문서 관리자가 비교·승인하면 공통 문서에 새 통합 버전이 생긴다. 소유자가 자기 작업본을 승인하는 예외는 추가하지 않았다. 독립 검토자가 없는 문서는 먼저 공유 문서함의 관리자 구성을 정해야 한다. 제출 전 다른 사용자의 작업본은 기존 비공개 계약을 유지하며, 관리자는 제출된 정확한 저장본만 볼 수 있다.

현재 작업본의 마지막 저장본이 통합 완료된 뒤 공통 문서를 새로 열면 최신 공통 버전에서 다음 작업본을 만든다. 이전 작업본/기준 버전/후속 편집을 재작성하지 않는다. 작업본에서 **AI·서식 도구**는 저장·공동 세션 반납 후 기존 단독 편집기로 연결한다. 같은 작업본에 다른 참여자가 있으면 이 전환을 막는다. 이력은 실제 분기·통합 관계를 사용자별 열에 배치하며 화면 정렬을 위해 가짜 연결선을 만들지 않는다.

원본을 읽은 엔진이 문단 ID를 재번호화하는 등 구조가 바뀌면, 별개 문구 변경이어도 보수적인 구조 충돌로 자동 통합이 막힐 수 있다. 문단 ID 검증을 완화하거나 충돌을 덮어쓰지 않는다. 원본/작업본을 보존한 뒤 비교·조정해야 한다.

아래는 2026-10-27 구현한 동기화·저장 계약이다. 당시의 별도 공동편집 버튼은 위 진입 흐름으로 대체됐다. 단독 편집 중인 작업본은 먼저 저장하고 닫아야 한다. 공동편집이 진행 중인 같은 작업본은 일반 열기에서 자동으로 참여한다.

- 네이티브 한글 편집기에서 입력을 800ms 이상 멈추면 변경을 제출하며, 약 2초마다 저장된 상대 변경을 읽는다. 다른 문단·겹치지 않는 같은 문단 텍스트를 원문/현재/수정본의 3방향 비교로 병합한다. 계정 수와 브라우저 세션 수를 구분해 표시한다.
- 이는 연산 단위 CRDT/OT가 아니다. 같은 글자 범위, 같은 위치 삽입, 동시에 달라진 스타일 ID 정의, 식별하기 어려운 문단 재배열·구조 변경은 409로 멈춘다. 마지막 저장으로 덮어쓰지 않는다. 내 편집 다운로드와 같은 요청 재확인, 명시적 미저장 편집 폐기 후 재열기를 제공한다. 상대 커서는 표시하지 않는다.
- 제출·재배치 때 잠깐 입력을 막아 제출 이후 입력이 재로딩으로 사라지지 않도록 한다. IME 조합 중에는 제출하지 않고 임대 갱신만 한다. AI 제안·표준/블록 패널은 단독 편집에서 사용한다. 공동편집 중 파일을 새로 열지 말고 다른 문서는 문서함에서 연다.
- 공동편집은 문서당 최대 20개 세션, HWPX 10MB, 같은 텍스트 노드의 동시 병합 4,096자 범위다. 긴 단독 변경은 이 글자 수 병합 한도와 별개다. 문서·주석·표준 생성 한도를 완화하지 않는다.

## 저장과 재접속

`coedit_rooms`, `coedit_members`, `coedit_receipts`, `lease_logins`는 추가 테이블이다. 기존 HWPX·버전·원본을 변환하지 않는다. 공유 방의 세대 토큰으로 기존 단독 편집·복원·삭제 경로와 상호 배제한다. 서버는 문서 행을 잠근 후 현재 접근 권한, 로그인 범위, 참여 토큰과 방 세대를 재검증한다. 기존 원본 blob을 읽어 병합하고 손실 검사 및 기존 버전 게시 트랜잭션으로 새 버전·작성자·멱등 영수증을 함께 커밋한다. 응답 유실 후에는 같은 요청 ID/바이트/기준 버전으로 재확인한다.

참여 임대는 120초이며, 오래 입력하는 동안에도 약 20초마다 갱신한다. 다른 방/단독 편집으로 세대가 바뀌면 이전 편집자는 게시할 수 없다. 연결 오류·로그인 변경·충돌 때 브라우저의 기존 버퍼를 보존한다. 영구 오프라인 보관은 제공하지 않으므로 화면을 닫기 전 다운로드해야 한다. 타이머가 완전히 정지하는 절전·닫힌 브라우저는 자동 영구 잠금을 남기지 않는다.

단독 편집은 기존 만료 후 저장 거부를 유지한다. 사용자 **편집권 다시 연결**은 현재 토큰이 그대로인 경우에만 명시적으로 만료된 임대를 갱신한다. 이후 다른 세션이 발급됐다면 거부한다. 읽기 전용 화면은 저장본 SVG만 표시하며 문서 변경 명령을 실행하지 않는다.

브라우저는 `/auth/me`에서 얻은 불투명 로그인 범위를 작업 요청에 고정한다. 다른 탭의 로그인 교체로 쿠키가 바뀌면 기존 화면의 요청이 거부된다. 편집 토큰은 발급 로그인에도 결합하며, 로그아웃 시 그 로그인에 속한 참여/임대만 반납한다. 사용자 ID는 같아도 다른 로그인에서 편집 토큰을 재사용할 수 없다. 작업 전용 MCP 토큰은 별도 경로/작업 제한을 유지하며 초안 후보 제출만 가능하고 문서 직접 게시·편집권 발급은 할 수 없다.

## 검증 범위

`backend/tests/test_coedit.py`, `test_edit_login_fences.py`는 병합·경합·중첩 충돌·원본 보존·응답 유실·재시작·권한 회수·로그인 격리를 검사한다. `frontend/tests/coedit-real.spec.ts`는 별도 API와 실제 rhwp에서 두 탭의 네이티브 입력·충돌 버퍼·저장/재열기·읽기 전용 전환을 검사한다. 기존 PoC PostgreSQL/HTTPS 계정 검사에도 `deployment-tests/coedit-check.ts`를 연결한다. 합성 문서, 모델 호출 0회이며 Hancom/사람 검수와 구분한다.
