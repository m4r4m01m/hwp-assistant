# 문서 공동편집과 로그인 세션

## 2026-10-31 보완 — 작업본 전환

문서 제목 줄의 ‘작업본 선택’에서 공동 원본과 접근 가능한 별도 작업본을 전환한다. 현재 별도 작업본은 보라색으로 표시한다. 목록은 기존 문서 이력 권한/범위 제한을 따르며 리뷰용 메타데이터만 볼 수 있는 타인의 작업본은 열기 목록에서 제외한다. 읽기 전용 원본은 표시를 구분하고 열기 진입에서 현재 권한을 다시 확인한다.

미반영 상태에서는 반영 후 이동/작업본으로 보관 후 이동/계속 작성/버리기를 먼저 선택한다. 전환 취소 시 현재 작업본과 편집이 유지된다. 선택만으로 원본을 덮어쓰거나 통합하지 않으며 검토·통합은 기존 문서 이력을 사용한다.


## 2026-10-31 보완 — 충돌 해결 선택

‘내 편집 버리고 최신본 열기’는 앱 내 확인을 거쳐 같은 편집기에 최신 서버 버전을 로드한다. 취소/다운로드 실패 시 내 frozen 편집을 유지하고, 성공 후 미반영/중단 상태를 해제한다. 다른 참여자의 반영 내용과 기존 이력은 변경하지 않는다. 이전의 브라우저 confirm 이후 문서함으로 나가는 동작을 대체한다.

‘내 작업본으로 분리해 계속 작성’은 기존 `/coedit/revision`에 충돌 전 기준 버전과 내 frozen HWPX를 전달해 개인 수정안을 만든다. 저장 응답을 받은 뒤 해당 문서를 바로 열며, 원본 반영은 문서 이력의 검토·통합 절차를 따른다. 응답 유실은 같은 요청 ID/bytes로 재확인한다. 이미 별도 수정안에서는 중첩 분기를 만들지 않는다.


## 2026-10-31 보완 — 공통 작업 메뉴와 재접속

공동편집은 공통 사이드바의 반영/이력/다운로드/함께 작업 메뉴를 사용한다. 문서 상단에는 제목과 저장 상태만 표시하며 숨김·아이콘·펼침은 다른 화면과 같은 사용자 설정을 따른다. 미리보기 참여자 제어는 사이드바, 실제 읽기 전용 화면은 편집 영역 오른쪽(모바일은 아래)에 배치한다. 이동은 기존 미반영 확인을 거치며 UI 배치를 바꾸어 저장이나 승인 절차를 건너뛰지 않는다.

관찰 대상은 선택한 세션 ID와 서버가 제공한 계정 ID를 함께 기억한다. 기존 세션이 사라지면 같은 문서의 유효 peer 중 동일 계정이 하나일 때 새 세션으로 연결한다. 다른 계정이나 동일 계정의 여러 창을 임의로 고르지 않는다. 대상이 없으면 재접속 대기, 여러 창이면 선택 안내를 표시한다. 명시적으로 닫으면 대상도 지워 재접속 때문에 다시 열리지 않는다. 새 세션으로 연결할 때는 과거 프레임/수동 쪽 선택을 지우고 새 작성 위치를 따른다.

## 2026-10-31 보완 — 확대와 쪽 고정 구분

휠/± 버튼은 자동 따라가기를 해제하지 않는다. 배율만 기억해 다음 작성 쪽도 같은 배율로 표시한다. 드래그·방향키 위치 이동 및 이전/다음 쪽 직접 선택만 현재 쪽을 고정하고, **작성 위치 따라가기**는 고정을 해제한다. 아래의 “직접 조작하면 추적 중지”는 배율 조정까지 포함했던 과거 동작이며 이 절이 대체한다. 작성 쪽이 달라지면 새 작성 쪽 SVG를 먼저 전송하고, 문서 revision이 그대로여도 현재 문단 컨텍스트는 갱신한다. 새로운 쪽을 기다릴 때 이전 쪽 그림을 새 쪽 번호 아래 표시하지 않는다.

## 2026-10-30 후속 개선 — 실시간 미리보기 직접 탐색

미리보기에서 드래그로 위치를 옮기고 휠/± 버튼으로 배율을 바꾼다. 쪽 끝에서 80px 이상 더 끌거나 이전/다음 버튼, PageUp·PageDown으로 쪽을 넘긴다. 직접 조작 중에는 상대의 작성 위치를 따라가지 않으며 같은 페이지의 새 프레임에도 수동 위치를 유지한다. **작성 위치 따라가기**는 현재 작성 쪽과 자동 확대를 복구한다. 전체 쪽 수/보고 있는 쪽/상대 작성 쪽을 구분한다. 이 조작은 읽기 전용이며 작성자의 커서·문서·저장을 변경하지 않는다.

`/coedit/live`의 `watch_page`는 동일 문서의 유효 참여자에게만 요청된다. 작성자 브라우저가 실제 `pageCount()`/`getPageSvg()`로 현재 쪽과 요청된 쪽을 순차 렌더링하고 revision/epoch/base를 다시 확인해 공유한다. 서버는 `rendered_page`, `page_count`, `revision`을 받고 기준 버전 또는 revision이 달라지면 과거 페이지 캐시를 폐기한다. 최대 4쪽의 합계 SVG를 기존 참여자별 600,000자 한도 내에 보관한다. TTL 6초/최대 100개/동일 로그인 및 권한 검증은 유지한다. 여러 관찰자가 서로 다른 쪽을 요청하면 순환 처리하므로 지연이 늘 수 있다. 최신 프레임 대기 중 보존한 화면에는 갱신 안내를 표시한다. 미리보기는 서버 재시작 시 사라지며 역사 문서나 버전이 아니다.

## 2026-10-30 후속 개선 — 수동 반영과 수정 부분 자동 확대

추가 사용성 조정: 짧은 수정의 최소 표시 범위를 120×80에서 320×180 SVG 단위로 넓혀 과도한 확대를 줄이고 수정 위치 양쪽의 문맥을 표시한다. 고정 패널과 변경 범위에 따른 자동 줌아웃은 유지한다. 다른 참여자의 명시적 반영본은 약 2초 주기로 조회해 내 미반영 내용/IME 조합이 없으면 로드하며 완료 안내를 표시한다. 내 편집이 있으면 덮어쓰지 않고 새 반영본 대기 안내를 표시한다. 이후 내 명시적 반영 시 기존 3방향 병합을 수행하고 충돌은 멈춰 보존한다.

현재 개선 브랜치에서는 공동편집 자동저장을 제거했다. **변경사항 반영**만 HWPX를 게시하며 주기적 요청은 참여 상태와 다른 사람의 반영본을 조회한다. 내 미반영 내용이 있으면 다른 저장본을 로드하지 않는다. 화면 이동은 반영/수정안 보관/계속 작성/폐기를 명시적으로 선택한다. 반영 중에는 버퍼를 잠그고 동일 스냅샷·기준 버전·요청 ID로 응답 유실을 재확인한다. 개인 문서의 기존 단독 편집 복구 기능을 바꾸거나 새 자동 백업을 추가한 것은 아니다.

충돌 시 **별도 수정안으로 보관**은 `/coedit/revision`으로 현재 버퍼를 비공개 문서에 저장한다. 문서 잠금·접근 권한·세션·기준 버전·HWPX 검사를 통과해야 하며 원본 현재 버전은 바뀌지 않는다. 재시도는 같은 수정안을 반환하고 다른 내용의 요청 ID 재사용은 거부한다. 이미 수정안인 문서에 중첩 수정안을 자동으로 만들지 않는다. 기존 검토 요청/독립 승인/통합 절차를 사용한다.

**작성 화면 보기**의 폭은 고정한다. 실제 페이지 SVG 텍스트 위치와 기준 저장본 텍스트 차이로 표시 범위를 좁혀 확대하며, 같은 페이지에서 수정 영역이 커지면 줌아웃한다. 추가는 초록, 삭제 위치와 삭제 문구는 빨강이다. **쪽 전체 보기**로 전환할 수 있다. 기준 텍스트가 없는 페이지는 최초 관찰 이후 비교라고 표시하며 텍스트 위치를 확인하지 못하면 전체 페이지로 표시한다. 순수 서식 변경이나 비텍스트 객체를 정밀하게 비교하는 기능은 아니다. 미반영 내용은 입력을 잠시 멈춰도 공유 미리보기에 남는다. 미리보기는 실제 저장이나 다른 참여자의 편집 버퍼 적용이 아니다.

아래 자동저장 및 충돌 수정안 보관 미구현 설명은 이전 구현 기록이며 이 절이 대체한다.

## 2026-10-30 후속 개선 — 작성 중 문단 미리보기

참여자 상태의 **작성 화면 보기**를 선택하면 오른쪽에 상대가 입력 중인 문단을 표시한다. **쪽 전체 보기**는 해당 참여자의 실제 엔진 SVG 페이지를 표시한다. 본문 문단 컨텍스트를 얻을 수 없는 표·복합 서식은 페이지로 표시한다. 문단 텍스트는 앞 2,000자, 페이지 SVG는 600,000자 범위의 미리보기다. 전체 문서나 사용자 키 입력을 다른 편집기에 적용하지 않는다.

600ms 간격으로 직렬 요청하며, 실제 엔진의 변경 revision/문서 epoch/기준 버전을 확인한 결과만 공유한다. 고정 지연이나 토큰 애니메이션을 흉내 내지 않는다. `/coedit/live`는 동일 문서·방 세대·사용자·로그인·편집 권한을 검증하고 서버가 정한 작성자만 반환한다. sequence 역전을 무시하고 퇴장/만료 후 표시를 제거한다. 메모리 미리보기는 6초 후 정리하며 최대 100개로 제한한다. 재시작 때 사라지는 단일 API worker용 부가 기능이며 버전·blob 저장이나 AI 입력이 아니다. 미리보기 실패는 작성·저장 루프를 중단하지 않는다. 수신 SVG는 기존 안전 표시 필터를 거치고 읽기 전용으로 표시한다.

동시 접속만으로 자동 분기하지 않는다. 현재 변경 저장/충돌 보존과 명시적 별도 수정안 절차는 유지한다. 충돌 시 수정안으로 보관하는 추가 UX와 문서 내부 커서/연산 단위 공동편집은 아직 구현하지 않았다. 일반 다운로드는 **파일 → 현재 내용 파일로 저장**, 오류 복구는 **저장·동기화 다시 시도 / 작성 내용 백업**으로 표시한다.

## 2026-10-30 후속 개선 — 함께 편집하고 필요할 때만 수정안 분리

아래의 자동 개인 작업본 진입은 과거 구현 기록이다. 현재 개선 브랜치에서는 계정 기능을 사용하는 공유 문서를 열면 같은 원본의 공동편집에 바로 참여한다. 일반 열기는 새 문서·버전을 만들지 않는다. 열람자는 읽기 전용이며 개인 비공유 문서는 기존 편집기를 사용한다. 기존 작업본과 예전 열기 영수증은 보존하여 이미 완료된 옛 요청을 같은 ID로 재확인하면 당시 작업본을 반환한다.

문서 이력의 기본은 **버전 목록**이다. 현재 버전과 이름을 붙인 저장 시점을 먼저 표시하고 그 사이의 작성자별 저장 기록을 펼쳐 볼 수 있다. **버전 이름 남기기**는 선택한 불변 저장본에 이름을 추가하는 기능이며 새 HWPX를 만들거나 기존 작성자를 바꾸지 않는다. 이름이 있는 버전의 변경 비교는 조회 범위 안의 이전 이름 있는 버전부터, 개별 저장 기록은 직전 저장본부터 비교한다. 조회 범위가 잘린 경우 최근 기록이라는 안내를 유지한다. 최초 이름 저장의 재확인은 같은 이름일 때만 성공하며 다른 이름으로 조용히 덮어쓰지 않는다. 편집 권한·문서 소속을 확인하고 이름과 감사 기록을 함께 저장한다.

원본에 바로 반영하지 않고 검토할 변경은 **별도 수정안 만들기 → 검토 요청 → 승인 후 반영**을 사용한다. 기존 비공개 수정안·독립 검토자·동결된 제출본·원본 변경 시 재검토 계약을 유지한다. 실제 분기 트리는 **분기 보기**에서 확인한다. 이력 선택은 미리보기이며 **이 저장본 복원**을 명시적으로 선택할 때만 새 복원 버전을 만든다. 아래 동기화/충돌 보존 계약은 그대로 적용된다.

## 2026-10-30 진입 흐름 변경

계정 기능을 사용하는 공유 문서는 문서 이름 또는 이력의 **편집**을 누르면 내 작업본으로 열린다. 별도 공동편집 버튼은 없다. `/documents/{id}/edit-target`이 원본 잠금 아래 계정별 자동 작업본을 생성·재사용하며, `work_copy_entries`에 열기 요청 영수증을 저장한다. 동일 요청 재확인은 같은 작업본을 가리키고 다른 계정/문서에서 재사용하면 거부한다. 열람자는 작업본을 자동 생성하지 않고, 공유하지 않은 개인 문서와 계정 미사용 환경은 기존 편집기를 사용한다.

사용자별 작업본은 서로 다른 가지에 저장한다. 같은 작업본에 명시적으로 초대된 참여자만 그 작업본에서 아래 실시간 동기화를 함께 사용한다. **문서 이력·검토 → 통합 요청** 후 해당 수정에 참여하지 않은 문서 관리자가 비교·승인하면 공통 문서에 새 통합 버전이 생긴다. 소유자가 자기 작업본을 승인하는 예외는 추가하지 않았다. 독립 검토자가 없는 문서는 먼저 공유 문서함의 관리자 구성을 정해야 한다. 제출 전 다른 사용자의 작업본은 기존 비공개 계약을 유지하며, 관리자는 제출된 정확한 저장본만 볼 수 있다.

현재 작업본의 마지막 저장본이 통합 완료된 뒤 공통 문서를 새로 열면 최신 공통 버전에서 다음 작업본을 만든다. 이전 작업본/기준 버전/후속 편집을 재작성하지 않는다. 작업본에서 **AI·서식 도구**는 저장·공동 세션 반납 후 기존 단독 편집기로 연결한다. 같은 작업본에 다른 참여자가 있으면 이 전환을 막는다. 이력은 실제 분기·통합 관계를 사용자별 열에 배치하며 화면 정렬을 위해 가짜 연결선을 만들지 않는다.

원본을 읽은 엔진이 문단 ID를 재번호화하는 등 구조가 바뀌면, 별개 문구 변경이어도 보수적인 구조 충돌로 자동 통합이 막힐 수 있다. 문단 ID 검증을 완화하거나 충돌을 덮어쓰지 않는다. 원본/작업본을 보존한 뒤 비교·조정해야 한다.

아래는 2026-10-27 구현한 동기화·저장 계약이다. 당시의 별도 공동편집 버튼은 위 진입 흐름으로 대체됐다. 단독 편집 중인 작업본은 먼저 저장하고 닫아야 한다. 공동편집이 진행 중인 같은 작업본은 일반 열기에서 자동으로 참여한다.

- 네이티브 한글 편집기에서 입력을 800ms 이상 멈추면 변경을 제출하며, 약 2초마다 저장된 상대 변경을 읽는다. 다른 문단·겹치지 않는 같은 문단 텍스트를 원문/현재/수정본의 3방향 비교로 병합한다. 계정 수와 브라우저 세션 수를 구분해 표시한다.
- 이는 연산 단위 CRDT/OT가 아니다. 같은 글자 범위, 같은 위치 삽입, 동시에 달라진 스타일 ID 정의, 식별하기 어려운 문단 재배열·구조 변경은 409로 멈춘다. 마지막 저장으로 덮어쓰지 않는다. 내 편집 다운로드와 같은 요청 재확인, 명시적 미저장 편집 폐기 후 재열기를 제공한다. 상대 커서는 표시하지 않는다.
- 제출·재배치 때 잠깐 입력을 막아 제출 이후 입력이 재로딩으로 사라지지 않도록 한다. IME 조합 중에는 제출하지 않고 임대 갱신만 한다. AI 제안·표준/블록 패널은 단독 편집에서 사용한다. 공동편집 중 파일을 새로 열지 말고 다른 문서는 문서함에서 연다.
- 공동편집은 문서당 최대 20개 세션, HWPX 10MB, 같은 텍스트 노드의 동시 병합 4,096자 범위다. 긴 단독 변경은 이 글자 수 병합 한도와 별개다. 문서·주석·표준 생성 한도를 완화하지 않는다.

## 저장과 재접속

`coedit_rooms`, `coedit_members`, `coedit_receipts`, `lease_logins`는 추가 테이블이다. 기존 HWPX·버전·원본을 변환하지 않는다. 공유 방의 세대 토큰으로 기존 단독 편집·복원·삭제 경로와 상호 배제한다. 서버는 문서 행을 잠근 후 현재 접근 권한, 로그인 범위, 참여 토큰과 방 세대를 재검증한다. 기존 원본 blob을 읽어 병합하고 손실 검사 및 기존 버전 게시 트랜잭션으로 새 버전·작성자·멱등 영수증을 함께 커밋한다. 응답 유실 후에는 같은 요청 ID/바이트/기준 버전으로 재확인한다.

참여 임대는 120초이며, 오래 입력하는 동안에도 약 20초마다 갱신한다. 다른 방/단독 편집으로 세대가 바뀌면 이전 편집자는 게시할 수 없다. 연결 오류·로그인 변경·충돌 때 브라우저의 기존 버퍼를 보존한다. 영구 오프라인 보관은 제공하지 않으므로 화면을 닫기 전 다운로드해야 한다. 타이머가 완전히 정지하는 절전·닫힌 브라우저는 자동 영구 잠금을 남기지 않는다.

단독 편집은 기존 만료 후 저장 거부를 유지한다. 사용자 **편집권 다시 연결**은 현재 토큰이 그대로인 경우에만 명시적으로 만료된 임대를 갱신한다. 이후 다른 세션이 발급됐다면 거부한다. 읽기 전용 화면은 저장본 SVG만 표시하며 문서 변경 명령을 실행하지 않는다.

브라우저는 `/auth/me`에서 얻은 불투명 로그인 범위를 작업 요청에 고정한다. 다른 탭의 로그인 교체로 쿠키가 바뀌면 기존 화면의 요청이 거부된다. 편집 토큰은 발급 로그인에도 결합하며, 로그아웃 시 그 로그인에 속한 참여/임대만 반납한다. 사용자 ID는 같아도 다른 로그인에서 편집 토큰을 재사용할 수 없다. 작업 전용 MCP 토큰은 별도 경로/작업 제한을 유지하며 초안 후보 제출만 가능하고 문서 직접 게시·편집권 발급은 할 수 없다.
