# Codex 작업 인계

상태: 프로젝트 구현용 작업 지침 초안. 이 문서가 자동으로 적용되는 루트 `AGENTS.md`라는 뜻은 아니다. 실제 저장소의 기존 지침을 먼저 읽고 충돌을 확인한다.

## 1. 고정할 기준

작업 저장소는 `m4r4m01m/hwp-assistant`다. [프로젝트 기준선](project-overview.md), [개발 순서](development-plan.md), [시스템 설계](architecture.md)를 우선 읽는다. 현재 저장소 파일·구현·테스트를 확인한 뒤 작업하고, 문서에 적힌 기술 스택을 이미 구현된 사실로 취급하지 않는다.

유료 OpenAI API를 추가하지 않는다. HWPX 원본을 HTML/JSON으로 대체하거나 실시간 공동 편집을 범위에 넣지 않는다. 사용자 미승인 비용·외부 서비스·대규모 새 의존성을 추가하지 않는다. 모델 ID·내부 주소·인증값은 추정하거나 코드에 박아 넣지 않는다.

## 2. 트랙 A 첫 작업: 실제 LLM 최소 검증

**목표:** 개발용 모델을 실제 호출하여 초안·검토 기능 계약을 검증한다.

**범위:** 공통 LLM 어댑터, 설정 분리, 합성 입력, 구조화 출력 검증, 오류·취소 처리, 호출 근거 기록. 기존 앱 구조가 있으면 그 안에서 작은 변경으로 구현한다.

**완료 기준:** 초안과 검토 각각 실제 호출 증거가 있고, 입력하지 않은 사실을 채우는 오류 사례를 점검한다. 모델 ID·프롬프트 버전·응답 시간·스키마 통과 여부를 기록한다. Mock은 Mock으로 명시하고 실제 AI 성공에 포함하지 않는다.

**제외:** HWPX XML 전체 생성, 원문 자동 덮어쓰기, 유료 API 우회, 모델 학습, 대규모 RAG.

## 3. 트랙 B 첫 작업: 편집기·HWPX 위험 검증

**목표:** 합성 HWPX를 실제 한글과 웹 사이에서 왕복하며 원본 보존과 편집 가능성을 확인한다.

**범위:** 편집기 버전/실행 경로 확인, 원본 보관, 무편집 재출력, 문단/표 수정, 비교 결과 기록. 통합 SDK 기능은 실제 코드·문서를 읽고 확인한다.

**완료 기준:** 원본 보관 해시 시험과 엔진 재출력 시험이 구분되어 있고, 한글에서 열기·서식·비대상 내용·재편집을 확인한다. 실패·미지원 요소를 숨기지 않는다.

**제외:** 모든 한글 기능 재구현, 원본을 파생 JSON만으로 대체, 시험 전 완전 호환 주장.

## 4. 공통 계약과 변경 관리

문서 ID·기준 버전·선택 범위·원문 해시·저장/AI 상태를 합의한다. 저장 성공은 서버 확정 뒤에 표시한다. 오래된 AI 제안과 기준 버전 불일치를 차단한다. 새 의존성은 버전·사용 목적·오프라인 실행 영향을 기록한다.

변경 전 관련 파일과 테스트를 읽고 작은 범위의 브랜치에서 작업한다. 사용자 코드를 임의로 삭제·덮어쓰거나 강제 푸시하지 않는다. 기존 원격 파일이 예상과 다르면 중단해 비교한다. 새 폴더 이름이나 문서 생성만으로 구현 완료를 보고하지 않는다.

```text
변경한 파일:
실행한 명령·테스트:
실제 결과와 증거:
실행하지 못한 시험 및 이유:
남은 위험·미지원 범위:
비용·외부 통신·새 의존성 변화:

```

현재 문서 묶음에는 앱 구현 코드, 테스트 실행 성적, GitHub 이슈 생성 결과가 포함되어 있지 않다. 보관된 ZIP에 언급된 코드를 실제로 복원했다고 해석하지 않는다.
