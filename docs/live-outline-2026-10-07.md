# 보이는 작성 과정, 초안 복구, 짧은 개조식 항목

2026-10-07 사용자 요청: 발표 중 초안이 만들어지는 과정을 보여주고, 새로고침 이후에도 한글 서식 초안을 확인하며, 긴 □ 문단을 약 2~3줄의 별도 항목으로 나눈다.

## 화면과 상태

실제 단계는 `내용 작성 → 문서에 입력 → 서식·페이지 배치 → 편집 가능`이다. Codex CLI는 현재 구조화된 최종 결과를 반환한다. 이번 변경은 모델의 토큰 스트리밍을 구현한 것이 아니다. 응답 전에는 작성 상태와 실제 경과 시간만 표시한다. 결과가 도착한 뒤에는 기존 rhwp exact command가 성공한 문단만 진행 화면에 누적한다. 현재 문서 입력 단계와 완료된 문단 수를 표시하고, 배치가 끝나면 실제 rhwp 편집기를 노출한다.

진행 화면은 제목의 파란 선과 개조식 계층을 보여주는 HTML 미리보기다. 최종 페이지 배치라는 표시는 하지 않는다. 최종 결과는 rhwp HWPX이며 편집 가능하다. `작성 과정 천천히 보기`는 완료된 문단을 220ms 간격으로 표시하여 발표 중 읽기 쉽게 한다. 이를 꺼서 표시 대기를 줄일 수 있다. 허위 모델 진행률이나 작성 중인 것처럼 보이는 가짜 본문은 없다. 준비용 placeholder와 중간 작업용 페이지는 노출하지 않는다.

현재 Chrome 탭은 연결된 도구에 없어 사용자가 본 화면 자체는 직접 관찰하지 못했다. 서버에서는 최근 작업 `218f7f05-4e9c-451b-816e-91b0b415c2c0`가 ready이고 preview 준비 기록은 없는 것을 확인했다. 이를 특정 브라우저 캐시 결함으로 단정하지 않았다. 개선 사항은 다음과 같다.

- 최근 작업을 선택하면 목록의 옛 상태 대신 최신 작업 상세를 조회한다.
- 같은 탭에서 보고서 화면을 다시 열면 sessionStorage의 최근 작업 ID로 서버 상태를 복구한다. 미확정 초안은 같은 고정 preview를 다시 연다. 저장한 작업은 최근 목록에서 선택하면 실제 저장 문서 편집기로 연결하며, 새 요청 화면의 접근을 막지 않는다. 목록의 진행 상태도 현재 조회 결과로 갱신하고 긴 제목을 패널 안에서 줄바꿈한다.
- 로컬 진단 서버는 `Cache-Control: no-cache`로 앱 응답을 재검증한다. 새 번들을 만든 뒤 실제 제공되는 앱·엔진 바이트를 다시 검사한다. 기존 CSP·인증·엔진 빌드 보호를 낮추지 않는다.
- 사용자의 기존 탭을 조작하거나 강제로 새로고침하지 않는다. 미확정 직접 편집 내용은 새로고침으로 잃을 수 있어 기존 경고와 복구용 다운로드를 유지한다. 복구하는 것은 서버에 고정된 초안이다.

## 2~3줄 항목

생성 계약은 `korean-report-v3-short-items`다. □ 하나에는 하나의 논점을 담고 60~85자 안팎을 목표로 하며, 길거나 다른 논점이면 새 □ 문단을 쓰도록 지침을 바꿨다. 절당 문단은 최대 9개를 허용하고 기존 1500자 제한을 유지한다. 무조건 □·ㅇ·- 3문단만 작성하던 제약을 제거했다. 출처·조건·사실을 삭제하는 축약은 하지 않는다.

`report_outline.py`는 새 preview 계획을 만들 때 기호 문단을 표준 15pt·내어쓰기에서 3줄 이내를 목표로 나눈다. 문장 끝을 우선하고 어절 경계를 사용하며, 공백을 포함한 모든 원문 문자를 보존한다. □ 항목은 새 □로, 보조 설명 ㅇ·-는 같은 계층의 새 항목으로 나눈다. 새 기호는 계획에 명시되어 exact command 적용과 영수증 검증의 대상이다. 출처 ID를 버리거나 새로운 사실을 작성하지 않는다. 새 계획만 변경하며 기존 draft JSON·고정 preview·승인본·원본·과거 버전에는 소급 적용하지 않는다.

3줄은 지정 서식에서의 목표이며, 한컴의 다른 글꼴·사용자 직접 편집·매우 긴 공백 없는 토큰까지 동일한 행 수를 보장하지 않는다. 모델이 의미 단위의 짧은 항목을 작성하도록 하는 생성 지침과, 길어진 결과를 보존하며 분리하는 표시 전 처리를 구분한다.
