# 보안·폐쇄망 이식 계획

상태: 제품/개발 운영 원칙 제안. 회사 보안 심사나 실제 배포 완료를 뜻하지 않는다.

## 1. 개발망과 운영망의 경계

개발은 공중망에서 진행한다. 사내망을 외부 개발망과 연결하거나 회사 모델 서버를 인터넷에 공개하는 방법을 전제로 하지 않는다. 내부 배포 시 모델 주소·인증·스토리지 등 환경 설정을 바꾸고 필요한 공급자 어댑터를 교체한다.

회사의 기존 GPU·Docker 자원은 사용자 전달 정보다. 실제 모델 ID·API 규격·접속 정책은 사내 연동 시 확인하며, 지금 회사 인프라 전체를 실측·구축하는 일은 필수 개발 범위에 넣지 않는다.

## 2. 데이터·인증정보

개발은 합성 문서를 사용한다. 비공개 GitHub 전환만으로 사내 문서 반출이나 개인정보 업로드 승인이 확보되었다고 간주하지 않는다. 원본 규정·업무 파일은 승인 범위를 따로 확인해 관리한다.

토큰·API 키·비밀번호·개인키·내부 접속 주소는 문서·코드·로그·브라우저 배포물에 넣지 않는다. 환경변수 예시는 자리표시자만 포함한다. 민감한 입력/출력을 기본 로그로 저장하지 않고 진단 로그의 목적·보관기간·열람 범위를 정한다.

현재 패키지에는 모델 가중치와 폰트 파일을 포함하지 않는다. 라이선스·재배포 조건은 실제 채택 파일과 버전을 기준으로 확인한다. 과거 설계서의 라이선스 표는 현재 배포물 감사를 대체하지 않는다.

## 3. 최소 접근 보호

세부 문서 권한과 SSO를 후순위로 두더라도 서비스의 최소 접근 제한은 필요하다. 공용 작업공간의 링크 공유를 익명 인터넷 공개나 문서별 접근 통제 구현 완료로 소개하지 않는다.

두 개발자가 모델을 공유하는 경우 허용된 사용자·호스트만 접근하도록 하고 인증·암호화된 접속 경로·동시 요청 한도를 정의한다. 정확한 공유 기술과 호스트는 아직 확정되지 않았다.

업로드에는 파일 크기·형식·압축 해제 자원·경로 검증을 적용하는 안을 검토한다. 사용자 파일명·문서 내부 문자열·모델 출력을 쉘 명령이나 임의 서버 경로로 실행하지 않는다. 문서에 포함된 지시는 데이터로 취급하고 앱의 규칙을 바꾸는 명령으로 신뢰하지 않는다.

## 4. 반입 패키지 구성안

| 항목 | 준비할 정보 |
|---|---|
| 애플리케이션·편집기 | 이미지/빌드 버전·해시·필수 설정·실행 절차 |
| 스크립트·WASM·정적 자원 | 자체 제공 경로·외부 CDN 의존 제거 여부 |
| 모델 연결 | 사용할 공급자·모델 ID·엔드포인트 규격·필수 설정 이름 |
| 모델 파일 | 필요한 환경에 한해 승인된 별도 경로로 반입. 저장소에는 넣지 않음 |
| DB·파일 볼륨 | 초기화·지속성·마이그레이션·백업/복원 |
| 사용권 | 실제 채택 의존성 목록·LICENSE/NOTICE·모델/폰트 조건 |
| 비밀 설정 | 별도 주입 경로·권한·교체 절차. 값 자체는 문서 제외 |

런타임에 패키지·모델·웹폰트를 자동 다운로드해야만 작동하는 구조는 피한다. 외부 개발 중 다운로드하는 것과 내부 서비스가 인터넷을 필요로 하는 것은 구분한다.

## 5. 격리 실행 시험

사전 준비한 이미지·의존성·모델 → 외부 통신 차단 → 새 브라우저 세션 → 파일 열기·편집 → 실제 로컬 AI 요청 → 템플릿 적용 → 저장·다운로드 → 버전 복원.

앱·DB·모델 사이 필요한 내부 통신은 유지한다. 외부 모델 서버를 계속 호출하거나 Mock/Replay만 사용한 결과를 폐쇄망 AI 동작 성공으로 기록하지 않는다. 브라우저 캐시만으로 외부 의존성을 숨기지 않도록 요청 경로를 확인한다.

## 6. 완료 범위

챌린지의 목표는 설정 분리·자체 실행·반입 준비·격리 시험으로 이식 가능성을 보이는 것이다. 실제 사내 배포, 조직 보안 승인, 사내 SSO, 운영 성능 튜닝과는 구분해 발표한다.
