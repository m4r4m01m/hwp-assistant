# HWPX 호환성 검증 계획

상태: 시험 계획과 판정 기준 초안. 실제 한글·rhwp 실행 결과는 이번 문서 정리에 포함되지 않는다.

## 1. 품질 원칙

한글에서 만든 문서를 웹에서 편집한 뒤 한글에서 다시 열고 편집할 수 있어야 한다. 파일이 열리는 것만으로 성공 판정하지 않는다. 내용·스타일·배치·개체·편집 가능성을 함께 본다.

최초 업로드 원본과 모든 게시 버전은 보존한다. 엔진 무편집 왕복은 원본 그대로 다운로드하는 시험과 다르다. 편집 결과의 전체 파일 해시가 달라지는 것 자체를 오류로 보지 않고, 요청 변경과 비대상 내용 보존을 확인한다.

## 2. 시험 환경 기록

시험마다 한글 버전·OS·브라우저·편집기 commit/빌드·폰트 구성·입력 문서 해시·수정 동작·출력 파일을 기록한다. 사용 가능한 적법한 외부 한글 환경으로 시작하고 실제 회사 환경의 최종 적합성은 별도로 남긴다.

| 문서군 | 대표 확인 요소 |
|---|---|
| 기본 본문 | 제목·문단·글자/문단 서식·목록·페이지 나눔 |
| 표 | 셀 병합·너비/높이·테두리·문단·여러 쪽에 걸친 표 |
| 페이지 | 용지·여백·머리말/꼬리말·쪽 번호 등 사용 요소 |
| 개체 | 문서에서 사용하는 이미지·도형·기타 개체와 위치 |
| 복합 문서 | 본문·표·개체가 섞인 반복 편집 및 템플릿 삽입 |

이는 지원 완료 목록이 아니라 시험 대상으로 확인할 목록이다. 대표 문서 수·문서별 허용 차이는 시험 전 합의한다. 외부 테스트에는 합성 문서를 사용한다.

## 3. 필수 시험

| ID | 시험 | 합격 근거 |
|---|---|---|
| H-01 | 원본 업로드→원본 다운로드 | 입출력 원본 해시 동일 |
| H-02 | 웹 로드→엔진 재출력, 무편집 | 한글에서 내용·서식·개체의 비의도 변화 확인 |
| H-03 | 문단·제목·표 편집→한글 열기 | 요청 변경 반영, 비대상 영역 보존, 재편집 가능 |
| H-04 | 한글 수정본→웹 재등록·편집 | 대상 문서/기준 버전 식별, 변경 반영 |
| H-05 | 반복 왕복 | 반복 횟수 기록, 누적 내용 누락·서식 손상 없음 |
| H-06 | AI 승인 적용·템플릿 삽입 | 대상 변경과 스타일/리소스 보존 |
| H-07 | 저장 실패·오래된 탭·중복 요청 | 최신·원본 버전 보호, 복구 가능한 상태 |
| H-08 | 버전 복원 | 과거 파일 불변, 새 복원 버전 생성, 한글 재열기 |

## 4. 평가 방법

구조 비교에서는 텍스트·문단·표·개체와 연결 자원을 확인한다. 시각 비교에서는 한글과 웹의 페이지 배치·줄바꿈·폰트·표 크기를 본다. 시각 유사도만으로 데이터 보존을 판정하지 않는다.

글이 늘어나 쪽수가 증가하는 정상 조판 변화와 비대상 요소가 사라지거나 겹치는 손상을 구분한다. 비교 전 문서별 의도된 변화와 허용 범위를 기록한다.

## 5. 실패 시 처리

미지원 요소와 확인된 손실을 숨기지 않는다. 편집 제한·읽기 전용·게시 차단은 데이터 보호 조치일 뿐 호환 성공이 아니다. 손상이 확인된 결과는 정상 최신 버전으로 게시하지 않고 원본과 복구 후보를 보존한다.

검사기가 모든 손실을 발견한다고 가정하지 않는다. 자동 검사로 확인 가능한 범위와 실제 한글 수동 검증 범위를 구분한다. 대표 문서군에서 내용 누락·파일 손상·수정 미반영 0건을 목표로 하되, 시험 전 달성했다고 쓰지 않는다.
