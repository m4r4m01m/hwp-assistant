## 2. 변경 이력의 읽는 법

초기안, v0.2, v0.3, v0.4는 2026-09-23 작성된 이력이다. 원문에 유료 API, 특정 모델 크기, 회사 장비 우선 실측, 운영 Ollama 의무화, HTML/JSON 중심 원본, 과거 WBS 역할이 남아 있더라도 최신 기준으로 재활성화하지 않는다.

v0.4 이후에는 LLM 우선 검증과 AI/시스템 병렬 흐름을 반영한다. 이번 v0.5는 이를 문서로 다시 묶은 **정리 버전**이며 새로운 제품 릴리스나 검증 완료 버전이 아니다.

2026-09-25 최초 문서 인덱스 생성 뒤 저장소 이전·비공개 전환 과정에서 조회가 실패해 문서 묶음만 별도로 보관했다. 2026-09-26 재시도에서는 조직 저장소 접근과 push 권한을 확인했다. 문서 반영 직전 main에는 최초 인덱스 커밋만 있었으므로 그 위에 현재 기준 문서와 보관본을 추가한다. 실제 반영 이력은 Git 커밋으로 확인한다.

## 3. 아직 결정하거나 검증할 사항

| 항목 | 확인할 내용 | 개발을 막지 않는 진행 방법 |
|---|---|---|
| 개발용 모델·호스트 | 실행 가능한 모델, 공유할 기존 장비, 접속 보호 | 실제 가용 모델로 계약·기능부터 시험 |
| 사내 모델 식별 | 정확한 모델 ID·API·인증·한도 | 공급자 어댑터 경계 유지, 성능을 추정하지 않음 |
| 편집기 채택 | rhwp 버전·라이선스·선택/저장 경로·한계 | 합성 HWPX로 먼저 실물 시험 |
| 한글 검증 환경 | 한글 버전·OS·폰트·대표 문서 | 이용 가능한 적법한 외부 환경에서 시작 |
| 최종 기술 스택 | 기존 제안과 실제 코드의 일치 여부 | 구현 착수 시 대조, 버전 고정 |
| 일정·담당 | 마감일·가용 시간·실명 역할 | 기간 없는 A/B 순서도로 관리 |
| 규정 검토 범위 | 승인된 규정 원문·버전·반출/활용 범위 | 합성 규칙으로 계약만 시험, 실제 조문 생성 금지 |
| 저장소 변경 관리 | 향후 브랜치 보호·연결 권한 변화·팀 작업과의 충돌 | 매 작업 전 현재 HEAD와 관련 파일을 확인하고 강제 푸시하지 않음 |

## 4. 재정리 시 지킬 기록 원칙

사용자 전달, 설계 제안, 실제 도구 확인, 실행 검증을 구분한다. 미확정 모델 이름을 임의 정정하지 않는다. 계획상의 인수기준을 달성 수치로 바꾸지 않는다. 현재 코드·이슈 상태를 읽지 못했으면 미확인으로 남긴다.
