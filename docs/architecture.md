# 시스템 설계

상태: 기존 설계 제안의 재정리. 실제 채택 기술·버전·코드는 구현 시 별도로 확정하고 대조한다.

## 1. 구성요소와 경계

| 구성요소 | 책임 | 맡기지 않을 책임 |
|---|---|---|
| 웹 화면 | 드라이브, AI 패널, 템플릿 탐색, 저장 상태 표시 | 인증정보 보관·모델 직접 공개 호출 |
| 편집기 어댑터 | 문서 로드·선택 영역 읽기·승인 변경 적용·HWPX 출력 | 모델이 만든 XML로 문서 전체 재생성 |
| API 서버 | 파일·버전·편집 세션·템플릿·AI 작업 조정 | 사용자 파일명을 실제 저장 경로로 신뢰 |
| 메타데이터 DB | 문서 식별·폴더·버전·작업 상태 | 원본을 파생 JSON만으로 대체 |
| 파일 저장소 | 업로드 원본과 불변 HWPX 버전 | 과거 버전 덮어쓰기 |
| LLM 어댑터 | 공급자별 통신·시간 제한·출력 검증 | 임의 외부 서비스로 자동 우회 |

제안 연결: 웹 화면 → API → DB/파일 저장소. 웹 편집기는 어댑터로 API에 결과를 전달한다. AI 요청은 API → LLM 어댑터 → 개발 모델 또는 사내 모델로 전달한다.

React/TypeScript 화면, FastAPI, PostgreSQL, 서버 영속 볼륨은 기존 초기 제안이다. 현재 설치·구현 사실이나 확정 버전으로 표시하지 않는다. 편집기 후보는 사용자가 제시한 `edwardkim/rhwp`이며 자체 실행과 실물 HWPX 시험을 거쳐 채택한다.

## 2. 문서 원본과 파생 데이터

문서의 기준은 HWPX 파일의 불변 버전이다. 텍스트·JSON·미리보기·AI 컨텍스트는 해당 버전에서 만든 파생 데이터다. 파생 정보에 문서 ID와 버전 ID를 연결해 오래된 결과가 최신 파일을 덮어쓰지 않도록 한다.

사용자 표시 파일명, 문서 ID, 내부 저장 키를 분리한다. 같은 파일명만으로 같은 문서나 새 버전이라고 판단하지 않는다.

| 엔터티 제안 | 주요 정보 | 불변 조건 |
|---|---|---|
| Document | id, folder_id, display_name, current_version_id, trashed_at | 이름 변경과 문서 정체성을 분리 |
| DocumentVersion | id, document_id, parent_version_id, storage_key, content_hash, source, created_at | 파일과 버전 기록은 게시 후 덮어쓰지 않음 |
| EditSession | document_id, session_id, base_version_id, expires_at | 만료된 세션으로 저장 확정 불가 |
| Template | id, kind, source_version_id, metadata, version | 원본·리소스·템플릿 버전 추적 |
| AiSuggestion | id, document_id, base_version_id, target, original_hash, proposed_text, status | 승인 전 파일 변경 없음 |

이 표는 DB 마이그레이션이 아닌 논리 모델이다. JSON 필드·자료형·색인·권한 모델은 구현 시 확정한다.

## 3. 저장 프로토콜 제안

저장 요청에는 문서 ID, 기준 버전, 편집 세션, 요청 식별자를 포함한다. 서버는 세션·기준 버전을 확인하고 편집기 출력 파일을 임시 보관해 검사한다. 검사 통과 후 불변 파일을 보관하고 DB의 현재 버전을 비교·갱신한다. 파일과 DB가 확정된 뒤에만 화면에 저장 완료를 알린다.

파일 저장소와 DB가 단일 트랜잭션이라고 가정하지 않는다. 저장 중단·DB 실패에 대비한 임시 파일 상태, 재시도 중복 방지, 고아 파일 정리 절차를 정의한다. 실패한 저장을 정상 버전으로 게시하지 않고 복구 후보를 보존한다.

자동 저장과 수동 저장은 같은 안전 경로를 사용한다. 서버 저장 성공과 브라우저에서 파일을 내려받은 상태는 별도로 표시한다.

## 4. 실시간 공동 편집 없이 충돌 방지

문서당 하나의 활성 편집 세션을 허용하는 안과 기준 버전 비교를 함께 사용한다. 화면 잠금만으로는 오래된 탭·늦은 요청을 막았다고 판단하지 않는다. 세션 갱신·만료·반납, 기준 버전 불일치, 중복 요청을 서버에서 처리한다.

복원은 과거 파일을 새로운 현재 버전으로 등록한다. 로컬 한글 수정본을 올릴 때 대상 문서와 기준 버전을 명시한다. 충돌 시 최신 문서 확인·별도 문서로 저장·재적용 등을 사용자에게 제시하고 자동 병합은 하지 않는다.

## 5. AI·편집기 통합 경계

AI는 선택된 범위에 대한 내용 제안을 만든다. 서버는 출력 스키마·대상·원문 일치 여부를 검증하고, 사용자가 승인한 변경만 편집기 어댑터로 적용한다. 표·문단의 위치 식별을 유지할 수 있는지 실제 편집기 기능을 확인한다. 확인 전 특정 SDK 함수 이름이나 구조 안정성을 가정하지 않는다.

AI 적용 역시 일반 편집과 동일한 저장·왕복 시험 경로를 따른다. AI·모델 서버가 중단되어도 파일 열기·편집·저장이 중단되지 않도록 분리한다.
